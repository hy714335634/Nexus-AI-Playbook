# 构建进度

构建进度页面让你实时了解 Agent 构建的每一步。当你提交 Agent 创建请求后，会自动跳转到此页面。

![构建进度](/images/build-progress.png)

## 构建流水线概述

每个 Agent 的构建由 **8 个专业 Builder Agent** 组成的 AI 团队协作完成，经历 **9 个阶段**。整个流程就像一条软件开发流水线：

```
你的需求 → [编排] → [需求] → [架构] → [设计] → [提示词] → [工具] → [代码] → [审查] → [部署] → 可用的 Agent
```

每个阶段的产出自动传递给下一阶段作为输入，形成完整的构建链条。

### 九个阶段详细说明

| 序号 | 阶段名称 | 负责 Agent | 核心工作 | 产出物 |
|------|---------|-----------|---------|--------|
| 1 | **编排调度** | Orchestrator Agent | 分析需求复杂度，制定构建计划，分配任务路由 | 构建计划、任务分配方案 |
| 2 | **需求分析** | Requirements Agent | 将自然语言需求转化为结构化规格，补全缺失信息 | 详细需求文档（功能清单、I/O 定义、约束条件） |
| 3 | **系统架构** | Architecture Agent | 设计 Agent 技术架构，规划组件和集成方案 | 架构设计文档、技术选型方案 |
| 4 | **Agent 设计** | Design Agent | 定义行为模式、交互流程、错误处理策略 | 行为设计文档、交互流程、响应模板 |
| 5 | **提示词工程** | Prompt Agent | 编写系统提示词，优化指令，定义角色人设 | YAML 格式系统提示词文件 |
| 6 | **工具开发** | Tools Agent | 开发 Agent 需要的工具函数，集成 API | Python 工具函数代码 |
| 7 | **代码开发** | Developer Agent | 编写 Agent 主程序代码，整合所有模块 | Agent 主程序 Python 代码 |
| 8 | **开发管理** | DevManager Agent | 代码审查、质量保证、集成测试 | 审查报告、质量验证结果 |
| 9 | **部署上线** | Agent Deployer | 部署 Agent 并使其可被调用 | 已部署的 Agent 实例 |

## 各阶段深入解读

### 阶段 1：编排调度 — "项目经理"开始工作

**Orchestrator Agent** 是流水线的起点，它负责：

1. **解读你的需求** — 理解你想要什么样的 Agent
2. **评估复杂度** — 判断需要开发多少工具、涉及多少集成
3. **制定计划** — 为后续 8 个阶段制定详细的执行计划
4. **分配资源** — 确定每个阶段需要关注的重点

这个阶段通常很快（约 30 秒），因为 Orchestrator 的主要工作是分析和规划，不涉及实际的代码开发。

### 阶段 2：需求分析 — "产品经理"梳理需求

**Requirements Agent** 将你的自然语言描述转化为精确的技术需求规格：

- 提取核心功能点并排列优先级
- 定义输入输出格式和数据类型
- 识别需要的外部服务和 API
- 明确行为约束和边界条件
- 生成结构化的需求规格文档

在 **引导创建模式** 下，这个阶段会通过多轮问答与你互动，帮你补全遗漏的信息。在 **快速创建模式** 下，Requirements Agent 会自主推断缺失信息并补全。

### 阶段 3：系统架构 — "架构师"设计技术方案

**Architecture Agent** 根据需求文档设计 Agent 的整体技术架构：

- 确定需要哪些组件（模型、工具、中间件）
- 规划组件之间的交互方式
- 选择最适合的模型配置
- 确定需要集成的外部服务和 API
- 设计数据流向和处理流程

**示例产出：** 对于"医学文献助手"，架构设计可能包括：
- 模型：Claude（用于理解和生成）
- 工具链：PubMed API 搜索 → PDF 解析器 → 引用格式化器
- 数据流：用户输入 → 论文搜索 → 全文获取 → 内容分析 → 结果输出

### 阶段 4：Agent 设计 — "设计师"定义交互体验

**Design Agent** 定义 Agent 与用户交互的方式和行为逻辑：

- 对话流程设计（用户说什么，Agent 如何回应）
- 多轮对话的上下文管理策略
- 错误和异常的处理方式
- 回复的风格和格式定义
- 边界行为的处理（用户提出 Agent 能力范围外的问题时）

### 阶段 5：提示词工程 — "提示词专家"编写指令

**Prompt Agent** 编写影响 Agent 表现最关键的系统提示词：

- 定义 Agent 的角色身份和专业领域
- 编写详细的任务指令
- 说明可用的工具及使用场景
- 设定回复格式和语言风格
- 定义安全边界和行为约束

::: info 提示词的重要性
系统提示词是决定 Agent 表现好坏的最关键因素之一。一个好的提示词就像是给 AI 的"岗位说明书"——越详细、越准确，Agent 的表现就越好。Prompt Agent 会根据需求和设计文档，自动生成高质量的提示词。
:::

### 阶段 6：工具开发 — "工具工程师"开发功能

**Tools Agent** 开发 Agent 需要的所有工具函数：

- 根据架构方案确定需要开发哪些工具
- 编写 Python 工具函数代码
- 定义每个工具的参数和返回值
- 对接外部 API（如 PubMed API、AWS API 等）
- 测试工具的功能正确性

**常见工具类型：**
| 类型 | 示例 |
|------|------|
| 文件处理 | 读取 CSV、解析 Excel、写入文件 |
| API 调用 | HTTP 请求、搜索 API、数据查询 |
| 数据分析 | 统计计算、数据清洗、格式转换 |
| 代码执行 | 运行 Python 脚本、Shell 命令 |
| 网络请求 | 网页抓取、API 对接 |

### 阶段 7：代码开发 — "软件工程师"编写代码

**Developer Agent** 将前面所有阶段的产出整合，编写 Agent 的主程序代码：

- 加载系统提示词
- 注册所有工具函数
- 实现对话接口
- 处理文件上传和多模态输入
- 实现会话管理和上下文保持

### 阶段 8：开发管理 — "技术经理"审查质量

**DevManager Agent** 是最后的质量把关环节：

- 逐行审查代码，检查是否有 bug 或安全隐患
- 验证工具函数是否能正确执行
- 检查提示词与代码是否匹配
- 确认 Agent 的行为是否符合设计文档
- 如发现问题，协调 Developer Agent 修复

::: warning
如果 DevManager 发现严重问题，可能会要求返回前面的阶段重新工作。这会增加构建时间，但能确保最终交付的 Agent 质量达标。
:::

### 阶段 9：部署上线 — "运维工程师"完成部署

**Agent Deployer** 执行最终的部署操作：

- 配置运行环境和依赖
- 将 Agent 注册到平台
- 支持两种部署模式：
  - **本地部署** — 直接在 Nexus-AI 服务器运行
  - **云端部署** — 发布到 AWS Bedrock AgentCore
- 验证 Agent 可以正常接受请求和响应
- 将 Agent 状态设置为"运行中"

## 构建指标

构建进度页面实时展示本次构建的关键指标：

| 指标 | 说明 | 意义 |
|------|------|------|
| **总耗时** | 从开始到当前的累计时间 | 了解整体构建速度 |
| **输入 Tokens** | 所有 Builder Agent 消耗的输入 Token 总量 | 了解资源消耗 |
| **输出 Tokens** | 所有 Builder Agent 生成的输出 Token 总量 | 了解资源消耗 |
| **工具调用次数** | Builder Agent 在构建过程中调用工具的总次数 | 反映构建的复杂度 |

::: tip 理解 Token 消耗
Token 是大语言模型处理文本的基本单位。输入 Token 代表 Builder Agent "阅读"了多少信息，输出 Token 代表它们"产出"了多少内容。复杂的 Agent 构建会消耗更多 Token。
:::

## 构建失败处理

如果构建过程中某个阶段失败，你会在时间线上看到 ❌ 红色标记。

### 排查步骤

1. **查看错误日志** — 点击失败的阶段，查看详细的错误信息
2. **分析失败原因** — 常见原因包括：

| 失败原因 | 说明 | 解决方法 |
|----------|------|----------|
| **需求不够清晰** | Requirements Agent 无法理解或规格化你的需求 | 使用引导创建模式，或提供更详细的需求描述后重新构建 |
| **工具开发失败** | Tools Agent 无法开发某个工具（如 API 不可用） | 检查需求中提到的服务是否可用，调整需求后重试 |
| **代码审查未通过** | DevManager Agent 发现代码质量问题 | 通常系统会自动重试修复，如持续失败请简化需求 |
| **系统临时异常** | 后端服务暂时不可用 | 等待一段时间后重新创建构建项目 |
| **资源限制** | 超出当前配额 | 联系管理员调整资源配额 |

3. **重新构建** — 根据错误原因调整需求后，创建新的构建项目

::: warning
构建失败不会影响你已有的 Agent 和数据。每个构建项目都是独立的。
:::
