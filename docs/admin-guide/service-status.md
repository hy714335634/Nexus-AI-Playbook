# 服务状态监控

服务状态页让你在一个界面里掌握平台的整体健康状况——各后端服务是否在线、系统资源占用、存储空间、基础设施连接，并能直接对服务做重启 / 停止 / 启动，查看实时日志。出问题时，这里通常是你第一个要看的地方。

::: info
本页所有操作需要相应权限：查看状态需读取权限，重启 / 停止 / 启动等操作需写入权限。
:::

## 打开服务状态

侧边栏「管理」→「服务状态」，或直接访问 `/admin/service-status`。

页面顶部提供一个到「配置管理」的快捷链接，方便你在排查后直接去调参数。

![admin-service-status](/images/admin-service-status.png)

## 界面速览

页面分为四个标签页：

| 标签 | 用途 |
|------|------|
| **总览** | 健康度评分、系统资源、服务列表、存储空间、基础设施连接 |
| **实时日志** | 按服务 / 级别 / 关键词实时查看日志流 |
| **Sandbox** | 沙箱运行时与节点状态（部署了沙箱能力时可见） |
| **服务管理** | 服务操作与运维通知订阅 |

## 总览：一眼看健康

「总览」标签默认打开，每 60 秒自动刷新一次，也可点「刷新」手动更新。

### 顶部指标

顶部有四个指标卡：

| 指标 | 含义 |
|------|------|
| **健康度评分** | 0–100 的综合评分，主要由服务在线率决定。≥80 为绿色（健康），50–79 为橙色（注意），<50 为红色（异常） |
| **在线服务** | 「在线数 / 总数」，例如 `8/8` |
| **内存使用** | 系统内存使用百分比，超过 80% 转红 |
| **磁盘使用** | 根分区磁盘使用百分比，超过 80% 转红 |

### 系统资源

「系统资源」区用进度条展示内存、磁盘、负载（load average）三项当前占用，进度条超过 70% 转黄、超过 90% 转红。

### 服务列表

平台由以下 8 个后端服务组成，每个服务一张卡片：

| 服务 | 端口 | 作用 |
|------|------|------|
| **API** | 8000 | 后端接口服务，前端与外部调用的入口 |
| **Worker** | — | 后台任务处理（如 Agent 构建、异步作业） |
| **Frontend（Web）** | 3000 | 前端界面服务 |
| **Avatar** | 8004 | 数字形象 / 头像服务 |
| **Event Scheduler** | — | 定时与事件调度 |
| **Sandbox Controller** | 8002 | 沙箱运行环境控制器 |
| **Bridge** | 8001 | Bridge 连接服务（浏览器扩展等） |
| **OTEL Collector** | 4318 | 可观测数据采集器 |

每张卡片显示：状态点（🟢 运行中 / ⚪ 已停止 / 🔴 异常）、PID、端口、运行时长、内存占用，以及操作按钮。

### 存储空间与基础设施连接

- **存储空间**：展示各类数据目录（Avatar 空间、工作空间、事件数据、Agent 环境、VM 镜像等）的占用大小与条目数。
- **基础设施连接**：展示数据库、缓存、对象存储等托管服务的连接状态（`connected` / `error`），便于快速判断是平台自身还是底层依赖出了问题。

## 服务操作：重启 / 停止 / 启动

在「总览」的服务卡片或「服务管理」标签，都能对单个服务执行操作：

1. 找到目标服务卡片。
2. 服务运行中时，显示「重启」和「停止」按钮；已停止时显示「启动」按钮。
3. 点击对应按钮，操作结果会以提示条反馈。约 2 秒后状态自动刷新。

「服务管理」标签还提供**「重启所有服务」**按钮，一次性重启全部服务。

::: warning
重启 `api`（API 服务）时会有短暂不可用——平台会异步排程重启，接口立即返回「已排程」，随后自动检测恢复。这期间界面可能短时无响应，属正常现象。
:::

::: warning
**停止服务会让相关功能立即不可用**（例如停止 Worker 会导致构建任务停止消费）。停止和重启都会记入运维告警。请在业务低峰期操作，非必要不要长时间停止关键服务。
:::

## 实时日志

「实时日志」标签让你不登服务器就能看日志流。

1. 顶部下拉选择日志来源：`API` / `Worker` / `Avatar` / `Event Scheduler` / `Sandbox Controller` / `Bridge` / `OTEL Collector`，或「全部混合」。
2. 可选按级别过滤：`DEBUG` / `INFO` / `WARNING` / `ERROR`，或全部级别。
3. 可选填关键词，只看包含该词的行。
4. 日志按级别着色（ERROR 红、WARNING 黄），实时滚动追加。
5. 用「暂停」冻结当前画面便于查看，用「自动滚动」开关控制是否始终跳到最新行。

::: tip
也可以在任意服务卡片上点「日志」按钮，直接弹出**该服务**的实时日志窗口，无需切到日志标签再筛选。
:::

## Sandbox 标签

如果部署启用了沙箱能力，「Sandbox」标签展示运行时类型、节点与虚拟机的在线 / 忙碌 / 空闲 / 失败统计，并支持启动节点、缩容、切换运行时、手动健康检查等操作。未启用沙箱的环境此标签可能为空或不显示。

## 运维通知订阅

在「服务管理」标签，你可以订阅运维告警通知（如服务重启、停止等事件）：

1. 添加订阅者（邮箱等投递地址）。
2. 平台在关键运维事件发生时向订阅者推送通知。
3. 不需要时可移除订阅者。

::: info
服务**停止**为 critical 级告警（服务将不可用），服务**重启**为 warning 级告警。订阅后可第一时间获知这些变更。
:::

## 运维助手（Ops Helper）

服务状态页内置 AI 运维助手，帮你用自然语言排查问题，而不用自己翻日志、拼指标。

### 打开与提问

点页面右下角浮动的**「Nexus 助手」**按钮打开助手面板，可切换「右侧停靠 / 居中大窗」两种形态。面板给出常见排查问题的建议按钮，例如：

- worker 为什么没在消费消息？
- 哪个服务最近在刷 ERROR？
- api 启动失败怎么排查？

也可在输入框直接描述故障现象或提问，例如「当前各服务运行状态如何？」。

### 会给什么形式的回答

助手以流式方式作答，会根据问题给出**结构化结果**。例如问「当前各服务运行状态如何？」，它会返回一张服务状态表（服务 / 状态 / PID / 端口 / CPU / 内存），把 8 个服务的实时指标一次列清。


::: warning
运维助手只做**只读诊断**——查状态、读日志、给排查思路。它**不会**替你重启或停止服务；这些操作仍需你在服务卡片上手动点按钮并承担确认责任。
:::

## 命令行操作（nexus-cli）

除了网页界面，`nexus-cli` 也提供了同一套服务管理能力，适合在服务器上或脚本里使用：

```bash
nexus-cli status              # 查看所有服务状态
nexus-cli start <service>     # 启动指定服务
nexus-cli stop <service>      # 停止指定服务
nexus-cli restart <service>   # 重启指定服务
nexus-cli logs <service>      # 查看指定服务日志
```

其中 `&lt;service&gt;` 取服务标识，如 `api`、`worker`、`web`、`avatar`、`event`、`sandbox`、`bridge`、`otel`。命令行操作与网页按钮效果一致。

::: tip
日常巡检建议优先用网页「总览」——一屏看齐健康度、资源与全部服务状态；需要在服务器上批量操作或写进运维脚本时，再用 `nexus-cli`。
:::

## 注意事项

- 出问题先看「总览」的健康度评分和服务列表，再用「实时日志」定位报错，必要时问运维助手。
- 重启 / 停止关键服务尽量安排在业务低峰期，`api` 重启期间会短暂不可用。
- 停止服务会立即中断相关功能，且记为 critical 级告警——非必要不要长时间停用。
- 运维助手只做诊断，不代替你执行重启 / 停止等有风险的操作。
- 「基础设施连接」显示 `error` 时，说明问题可能出在数据库 / 缓存 / 存储等底层依赖，而非平台服务本身。
