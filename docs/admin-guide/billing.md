# 用量与计费

「用量与计费」是一份**用量报告**：它把平台上的 Token 消耗按模型、用户、项目、应用四个维度归因，并让你为用户和应用设置 Token 配额。你可以用它回答"这个月谁用得最多""哪个模型吃掉了大部分 Token""这个应用还剩多少额度"这类问题。

::: info 关于"计费"
本页只展示**用量**（调用次数、Token 消耗、配额），不展示美元金额。底层模型价格经常变动，为避免误导，这里不做费用换算——你可以把 Token 消耗作为成本归因的基础数据，再按自己的合同价格核算。
:::

![admin-billing](/images/admin-billing.png)

## 打开用量报告

1. 在侧边栏点「管理」→「用量与计费」。
2. 页面右上角有**月份切换器**，默认显示当月。点击年月选择框可切换到任意月份，页面数据随之刷新。

页面采用左右两栏布局：

- **左侧（主栏）· 用户层面用量**：活跃用户、调用次数、Token 消耗、按模型 / 按用户 / 按项目的排行。
- **右侧（辅栏）· 平台层面用量**：平台内置助手（配置管理、审计追踪、运维等）自身的消耗。

页面下方还有独立的**应用用量（近 30 天）**区块。

## 读懂总览指标

左侧主栏顶部是四个关键指标（KPI），反映所选月份的整体用量：

| 指标 | 含义 |
|------|------|
| 活跃用户 | 当月有过调用的用户数 |
| 总调用次数 | 当月所有调用的累计次数 |
| 输入 Token | 当月输入（发给模型）的 Token 总量 |
| 输出 Token | 当月输出（模型返回）的 Token 总量 |

KPI 下方是**输入 / 输出占比**条，直观显示这个月的 Token 花在输入还是输出上。当输入占比很高（≥90%）时会给出提示——通常意味着上下文或提示词偏长，可作为优化方向。

## 按模型查看消耗

「按模型消耗」区块用环形图 + 表格展示每个模型的用量。表格列为：

| 列 | 含义 |
|------|------|
| 模型 | 模型标识（如 `anthropic.claude-opus-4-8`） |
| 调用 | 该模型当月被调用的次数 |
| 输入 | 输入 Token 数 |
| 输出 | 输出 Token 数 |
| 总 Token | 输入 + 输出合计 |

用它可以快速判断哪个模型是主要成本来源，进而决定是否把部分场景切换到更轻量的模型（模型档位在「设置」→「模型目录」中维护）。

## Top 用户与 Top 项目

- **Top 用户消耗**：默认按总 Token 从高到低显示前 5 名，点「展开全部」查看更多。上方有搜索框，可按**用户名 / 邮箱 / 用户 ID**过滤。
  - 表格含「配额用量」列，显示该用户当月已用额度百分比。**接近上限（≥80%）的行标黄，超限（≥100%）的行标红**并带警告图标。
  - 点击任意一行（或行尾的外链图标）进入该用户的**用量与配额详情页**。
- **Top 项目消耗**：按项目汇总 Token 消耗，分页显示（每页 5 条）。


## 查看单个用户的用量与配额

从 Top 用户列表点进某个用户，会看到该用户的：

- **近几个月用量趋势**（默认近 6 个月）；
- **本月按模型的用量分布**；
- **当前 Token 配额**及已用比例。

这是你排查"某人 Token 涨得异常"或"用户反馈被限流"时的第一站。

## 管理用户 Token 配额

在用户的用量与配额详情页，可以为该用户设置**月度 Token 配额**。配额由三部分组成：

| 项 | 作用 | 默认 |
|------|------|------|
| 月度 Token 预算 | 该用户每月可用的 Token 上限 | 无（不限） |
| 告警阈值（%） | 已用量达到该百分比时提示 | 80 |
| 超限即禁用 | 达到上限后是否停止该用户继续调用 | 关闭 |

保存后，用户列表的「配额用量」列会据此计算黄 / 红标记。

::: warning 配额修改会被审计
每次修改用户配额都会写入**审计日志**（可在「设置」→「[审计追踪](./audit.md)」中检索）。记录包含操作管理员、目标用户、新的预算值与阈值。请谨慎调整"超限即禁用"——开启后用户一旦超额将无法继续调用。
:::

## 应用用量与应用配额

页面底部的「应用用量（近 30 天）」区块，按应用汇总用量。表格列为：

| 列 | 含义 |
|------|------|
| 应用 | 应用名称与 ID |
| 访问量 | 近 30 天访问次数 |
| 调用 | 近 30 天调用次数 |
| 总 Token | 近 30 天 Token 合计 |
| 平均单次消耗 | 总 Token ÷ 调用次数 |
| 配额（累计） | 应用的 Token 预算与累计已用；无预算显示"不限" |

- 点每行的「展开模型 / 输入输出明细」可看到该应用按模型和按输入 / 输出方向的细分。
- 配额列可**直接行内编辑**：点编辑图标，填入新的 Token 预算并保存即可生效。已累计用量达到或超过预算的应用会被标记为超额。

::: tip 长期运行的应用
应用配额是**累计**口径（不按月清零）。给长期对外提供服务的应用设预算时留足余量，或按需将其设为"不限"，避免额度耗尽后应用被判为超额。
:::

## 平台内置助手用量

右侧辅栏统计**平台自带 AI 助手**（如配置助手、审计助手、运维助手）自身消耗的 Token，按模块分组，展开后可进一步看到按模型和输入 / 输出的细分。这部分与终端用户的业务调用分开统计，方便你评估平台内置能力本身占用了多少用量。

## 说明与常见问题

::: info 本页没有独立的 AI 助手
「用量与计费」页面本身不带浮动 AI 助手。如果你想用自然语言查"谁改了配置""有无异常登录"这类问题，请到「设置」→「审计追踪」使用**审计助手**；想按自然语言调参降本，请到「设置」→「配置管理」使用**配置助手**。
:::

- **看不到费用金额**：这是刻意设计，见页首说明。请以 Token 消耗为准做成本核算。
- **某用户 / 应用一直显示"-"或"不限"配额**：表示尚未为其设置预算，属正常状态，不影响用量统计。
- **切换月份后数据变空**：说明该月没有用量记录，换回有活动的月份即可。
