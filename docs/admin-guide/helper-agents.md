# 内置 AI 助手（管理员）

Nexus-AI 在多个管理页面内置了 AI 助手（界面上统称「Nexus 助手」）。你可以用自然语言完成排障、配置、审计等日常管理——问它一句话，它就地给你答案、表格、建议，或一个可点击的按钮。

这些助手都遵循同一条底线：**只在各自页面工作，只读取该场景的数据，涉及改动的操作一律先生成"待确认提议"，由你点确认才生效**——它们不会绕过你直接改动系统。

## 助手一览

面向管理员的日常管理，有三个助手直接嵌在管理页面里：

| 助手 | 所在页面 | 能帮你做什么 |
|------|----------|--------------|
| 运维助手 | 服务状态 | 排障、评估服务健康度、提议重启（需确认）、分析错误日志 |
| 配置管理助手 | 配置管理 | 用自然语言找参数、解释参数、给调整建议、配置体检 |
| 审计追踪助手 | 审计追踪 | 审计问答、区间总结、生成合规报告 |

另有几个助手服务于「创建」类工作流（应用生成、任务发布、工具审查、技能蒸馏），面向使用者，详见用户手册；本篇末尾的[管理内置助手](#管理内置助手)会说明如何统一开关与选型。

## 通用用法

不管是哪个助手，用法都一样：

- **打开方式**：多数页面右下角有浮动的「Nexus 助手」按钮，点开即用；配置管理页额外在顶部内置了「想调什么，直接说」搜索框。
- **放大窗口**：面板内点「切换到居中大窗」可切换到居中大窗，方便看长回答。
- **建议问题**：面板里预置了几个常见问题按钮，点一下就能问，不必手打。
- **回答形式**：可能是纯文字、结构化表格，或末尾附一个可点击按钮（跳转到对应页面、或直接把筛选条件应用到当前列表）。
- **护栏**：助手以只读为主；任何会改动系统的动作都会先变成一个"待确认提议"，你确认后才执行；助手不会读写密钥、密码等敏感项。

## 运维助手

**用途**：在服务状态页帮你排障、看服务状态、分析错误日志，并在需要时提议重启服务。

**入口**：侧边栏「管理」→「服务状态」→ 页面右下角「Nexus 助手」。

> **场景**：周一早上用户反馈"构建一直卡住不动"。你打开服务状态页，点「Nexus 助手」，输入"worker 为什么没在消费消息？"。助手自动聚合 Worker 最近的错误日志，告诉你"Worker 进程 15 分钟前因 OOM 被系统终止，建议重启"，并生成一个「重启 Worker」待确认按钮——你点确认，Worker 恢复，队列开始消费。整个过程不需要 SSH 到服务器看日志。

![admin-service-status](/images/admin-service-status.png)

**能问什么**：助手覆盖四类运维诉求：

1. **问题排查**：描述故障现象，它会去查日志取证、定位可能的根因。
2. **服务状态评估**：问"当前各服务运行状态如何？"，它会给出各服务的运行状态、健康度与资源占用。
3. **服务重启**：要求重启某个服务时，它会生成一个"待确认提议"（见下方护栏），不直接执行。
4. **错误日志分析**：聚合高频错误、跨服务做时间关联，帮你定位连锁故障。

面板里的建议问题示例：「worker 为什么没在消费消息？」「哪个服务最近在刷 ERROR？」「api 启动失败怎么排查？」。

**回答形式**：状态类问题通常返回一张表格（服务 / 状态 / PID / 端口 / CPU / 内存）；排障与分析返回文字结论。如果你让它"生成/保存报告"，它会把完整报告存进它的工作空间，保存后你可以下载。

::: warning 护栏
- 运维助手是**只读**的：只能查看固定日志与服务状态、提议重启、把报告保存到工作空间，**不能改配置或执行任意命令**。
- **重启需确认**：只有对 Worker、Frontend（Web）、Avatar、Event Scheduler 这四个服务，助手才会生成"待确认提议"；真正重启由你在界面点确认后才触发。
- 对 API、Bridge、Sandbox Controller、OTEL Collector 的重启，以及"停止"任何服务的请求，助手会**礼貌拒绝**——这些操作请在服务列表用对应的「重启」/「停止」按钮手动执行，并自行评估影响。
:::

## 配置管理助手

**用途**：在配置管理页用自然语言找参数、看懂参数、拿到调整建议，并对整套配置做体检。

**入口**：侧边栏「设置」→「配置管理」。这个助手有三个入口：

> **场景**：你想降低平台的 AI 调用成本，但不确定该调哪些参数。在配置管理页的「想调什么，直接说」搜索框输入"降低使用成本"，点「AI 搜索」。助手语义匹配出 3 个相关参数（Prompt 缓存开关、轻量模型选型、对话管理策略），逐一解释它们对成本的影响，并给出建议值——你点建议卡片上的「填入」按钮，值自动填入对应参数框，确认后点「保存」即生效。这比翻文档找参数名、猜取值范围要快得多。

- 页面顶部「想调什么，直接说」搜索框；
- 页面右下角「Nexus 助手」浮动面板；
- 每个参数卡片上的「问 AI：作用与调整影响」按钮（针对单个参数提问）。

![settings-config](/images/settings-config.png)

**能做什么**：

1. **找参数**：用自然语言（而非精确关键词）描述你的目标，它做语义匹配帮你定位相关参数。
2. **解释参数**：说明参数作用、当前值是否合理、以及改动是**热加载**（新会话即时生效）还是**需重启**。
3. **给调整建议**：有明确建议时，会给出可一键填入参数框的建议值和一句话理由。
4. **配置体检**：点页面上的「配置体检」按钮，助手从成本、性能、可靠性、安全/合规四个维度审视当前全部配置，只报告真正值得注意的问题，并按严重程度排序。

面板里的建议问题示例：「我想降低使用成本」「对话经常丢失上下文怎么办」「prompt 缓存是干嘛的，建议开吗」「哪些参数改了需要重启服务」。

**回答形式**：文字解释 + 建议卡片（点一下把建议值填进对应参数框）+ 体检发现列表。

::: warning 护栏
- 助手**只会建议参数清单中存在、且满足其类型/范围/枚举约束的参数**，绝不会建议密钥、密码等敏感项。
- 建议只是"填入待保存"——填进去后仍需你确认并点「保存」才真正生效。
- 分清**热加载**与**需重启**：热加载项保存后下个新会话即生效，需重启项要重启对应服务后才生效。
- 自然语言搜索可能"零命中"（返回"AI 命中 0 个相关的参数"）——这是正常结果，换个说法或关键词再试。
:::

## 审计追踪助手

**用途**：在审计追踪页做审计问答、区间总结，并生成面向合规的审计报告。

**入口**：侧边栏「设置」→「审计追踪」→ 页面右下角「Nexus 助手」。

> **场景**：安全团队问你"上周有没有人尝试越权操作？"。你打开审计追踪页，时间范围选「近 7 天」，点「Nexus 助手」，输入"有没有越权尝试或失败登录"。助手从审计数据中提取出 2 条失败登录记录和 1 条权限不足的 API 调用，告诉你具体时间、用户和 IP，并附一个「查看相关记录」按钮直接跳到已筛选的日志列表。你不用手动翻页逐条看日志，也不用写查询语句。

![settings-audit](/images/settings-audit.png)

**能做什么**：

1. **审计问答**：问"谁改了什么、何时改的、有没有失败登录或越权尝试、哪个用户操作最频繁"这类问题。
2. **区间总结**：点「区间总结」按钮，得到当前范围内审计活动的简明要点（活动量、最活跃操作人、最常被改的资源、风险信号）。
3. **生成合规报告**：点「生成合规报告」按钮，生成一份面向 GxP / 21 CFR Part 11 的 Markdown 合规报告（含概述、关键变更、访问控制、异常与风险、结论与建议）。
4. **发送到 SNS**：点「发送到 SNS」按钮，把结果推送到审计通知主题。

面板里的操作按钮（区间总结 / 生成合规报告 / 发送到 SNS）都标注了「范围跟随当前筛选条件」——它们的处理范围就是你在页面上选的时间范围（近 7 天 / 近 30 天 / 近 90 天）。

**回答形式**：结构化的文字总结（如"今天共有 8 条登录记录，均为成功登录，来自两个 IP……"），末尾常附一个可点击按钮（如「查看今日登录记录」，点击跳转到已按条件筛选的审计日志）；合规报告则以完整 Markdown 呈现。

::: warning 护栏
- 助手**只依据当前范围内的服务端审计数据**作答；数据不足时它会明说"当前范围内无相关记录"，不会编造事件。
- 区间总结与合规报告都基于你所选的时间范围，导出/发送前请确认范围选对了。
:::

## 面向创建流程的助手

以下助手不是浮动按钮，而是嵌在各自的创建向导 / 构建流程里，主要面向使用者（详细步骤见用户手册）。作为管理员，你主要关心它们是否开启、用什么模型（见下一节）。

| 助手 | 在哪里出现 | 做什么 |
|------|-----------|--------|
| 应用生成 | 应用中心「新建应用」→ 快速创建向导 | 根据描述 + 绑定 Agent 生成一个可发布的单文件应用页面 |
| 任务发布 | 任务面板的自然语言建任务入口 | 把一句目标转成可执行任务方案（资源匹配 + 验收标准 + 调度方式） |
| 工具审查 | 工具构建流程 | 审查用户上传的脚本，输出结构化工具清单与审核建议 |
| 技能蒸馏 | 技能构建流程 | 把一段对话历史提炼成可复用的技能 |

::: tip
用「快速创建」向导（应用生成助手）发布应用时，有效期默认 7 天。长期要用的应用记得在发布弹窗把有效期改成「永久（无限期）」。
:::

## 管理内置助手

所有内置助手的开关与选型都在配置管理页统一管理：侧边栏「设置」→「配置管理」，在搜索框里搜 `helper` 即可定位到相关参数。每个助手都可以单独配置：

| 配置项 | 作用 | 生效方式 |
|--------|------|----------|
| 是否启用 | 关掉后，对应页面不再出现该助手 | 热加载 |
| 使用的模型 | 指定该助手用哪个模型；留空则按档位（pro / lite）自动选用模型目录里的对应模型 | 热加载 |
| 档位（pro / lite） | 模型留空时生效——pro 档更强、成本更高，lite 档更省 | 热加载 |
| 是否允许页面联动 | 是否允许助手在回答里附带可点击的跳转/筛选按钮 | 热加载 |
| 是否启用工作空间 | 是否允许助手把报告等产物保存到工作空间供下载 | 热加载 |
| 最多工具轮次 | 运维、任务发布等会调用工具的助手，单次回答最多可用多少轮工具 | 热加载 |

::: warning 注意
- 以上都是**热加载**项：改动后对**下一个新会话**生效，无需重启服务。
- 助手默认走 **pro 档**模型（回答质量更高）。切到 lite 档更省成本，但复杂排障、合规报告等场景的效果可能下降——按你的用量与预算权衡。
- 各助手用哪些模型可选，取决于模型目录（侧边栏「设置」→「模型目录」）里已启用的模型。
:::
