# 模型目录与接入

模型目录是平台可选语言模型的总清单。作为管理员，你在这里决定哪些模型对平台开放、每个模型属于哪个档位、是否支持图片输入，并可在保存前逐个测试连通性。会话与 Agent 构建时能选到的模型，就来自这份目录。

## 模型目录能做什么

- 增删和编辑可选模型，按提供商（Anthropic、Amazon、Meta 等）分组管理
- 为每个模型标注**档位**（pro / standard / lite）和**视觉**能力
- 逐个**测试**模型是否可用（真实调用 Bedrock）
- 一键**与 Bedrock 核对**，自动对齐当前区域实际可用的模型
- 需要时**恢复默认**目录

## 打开模型目录

侧边栏「设置」→「配置管理」→ 页面顶部点「模型目录」（也可从配置管理页的快捷入口「模型目录 — 编辑可选模型列表 · 测试后保存立即生效」进入）。

进入后左上角有「返回配置管理」链接可退回。

![settings-model-catalog](/images/settings-model-catalog.png)

## 页面构成

顶部操作按钮：

| 按钮 | 作用 |
|------|------|
| 「添加提供商」 | 新增一个模型提供商分组 |
| 「与 Bedrock 核对」 | 与 AWS Bedrock 对齐当前区域实际可用的模型 |
| 「恢复默认」 | 把目录重置为平台默认清单 |
| 「保存」 | 保存改动（初始为禁用，改动后可点） |

每个提供商是一个可折叠分组，分组内有提供商名称输入框和「添加模型」按钮。

## 每个模型的字段

在提供商分组下，每个模型一行，包含以下字段：

| 字段 | 说明 |
|------|------|
| 模型 ID | Bedrock 模型标识，如 `global.anthropic.claude-sonnet-5`；必须与 Bedrock 实际可用 ID 一致 |
| 显示名 | 界面上展示给用户的名称，如 `Claude Sonnet 5` |
| 档位 | 下拉选择 `pro` / `standard` / `lite`（见下方「档位说明」） |
| 「视觉」 | 勾选框；勾选表示该模型支持图片 / 文档输入 |
| 「测试」 | 真实调用一次 Bedrock，验证该模型当前是否可用 |
| 删除 | 行首垃圾桶图标，移除该模型条目 |

## 档位说明

档位用来标记模型的成本 / 性能定位，便于按场景选型：

| 档位 | 定位 |
|------|------|
| `pro` | 能力最强、成本最高，适合复杂推理与构建任务 |
| `standard` | 能力与成本均衡，日常任务的通用选择 |
| `lite` | 轻量、低成本，适合高频、简单或延迟敏感的场景 |

## 能力标记

除档位外，目录还反映以下模型能力，多数无需你手动处理：

- **视觉**：勾选「视觉」的模型支持图片 / 文档输入；未勾选的仅支持文本。
- **工具调用**：所有模型均支持工具调用；对不支持流式工具调用的模型，平台会自动降级为非流式，无需额外配置。
- **temperature 参数**：新一代"思考型"模型（如 Claude Opus 4.6 及以上、Claude Sonnet 4.6、Claude 5 家族）不接受 temperature 参数，平台会自动适配。
- **Prompt 缓存**：Claude 与 Nova 家族支持 Bedrock Prompt Caching，有助于降低重复上下文的成本。

## 管理操作

### 添加提供商与模型

1. 点「添加提供商」，在分组的名称输入框填写提供商名称。
2. 在该分组下点「添加模型」新增一行。
3. 填写「模型 ID」和「显示名」，选择「档位」，按需勾选「视觉」。
4. 点该行的「测试」确认模型可用。
5. 确认无误后点顶部「保存」。

### 测试模型连通性

每个模型行都有「测试」按钮，它会真实调用一次 Bedrock。上线新模型或修改模型 ID 后，建议先测试通过再保存，避免用户选到不可用的模型。

### 与 Bedrock 核对

点「与 Bedrock 核对」可自动对齐当前 AWS 区域实际可用的模型，减少手动维护。命令行下的等效操作是：

```bash
nexus-cli model reconcile
```

### 恢复默认

「恢复默认」把目录重置为平台默认清单。

::: warning 注意
「恢复默认」会覆盖你所有自定义的提供商与模型条目，操作不可撤销。请先确认已导出或记录当前配置。
:::

### 保存与生效

改动保存后立即对**新会话**生效；进行中的会话不受影响。目录初始来自平台默认清单，你的改动会作为覆盖保存下来。

::: tip 提示
只有点「保存」后改动才会生效。仅测试而未保存不会改变对外可选的模型列表。
:::

## 在配置管理中指定默认模型

模型目录决定"有哪些模型可选"，而"默认用哪个"在配置管理里设置：

- 侧边栏「设置」→「配置管理」，找到「模型」参数（`bedrock.model_id`）。
- 该参数带**热加载**标记，切换后新会话即时生效，无需重启。
- 每个配置字段旁有「问 AI：作用与调整影响」按钮，可就该参数向配置助手提问。

配置管理页顶部的「想调什么，直接说」支持自然语言搜参数（如"降低使用成本""哪些改了要重启"）。若某次搜索零命中，换个关键词再试即可。

## 查看模型用量

模型的实际消耗在用量报告中按模型维度呈现：

- 侧边栏「管理」→「用量报告」（或 `/admin/billing`），查看「按模型消耗」，含调用次数与输入 / 输出 Token。

![admin-billing](/images/admin-billing.png)

## 常见问题

| 问题 | 处理 |
|------|------|
| 用户选不到某个模型 | 确认该模型已在目录中且已「保存」；用「测试」验证连通性 |
| 「测试」失败 | 核对模型 ID 是否与 Bedrock 实际可用 ID 一致；用「与 Bedrock 核对」对齐 |
| 改了目录但没生效 | 确认已点「保存」；生效仅针对新会话 |
| 不确定选哪个档位 | 复杂推理用 `pro`，日常任务用 `standard`，高频轻量用 `lite` |
