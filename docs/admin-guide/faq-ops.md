# 常见问题与排障

本章汇总管理员日常最常遇到的问题和排查思路。遇到故障先按下面的**总流程**定位，再跳到对应小节看具体处理办法。每一类问题都标注了应该先看哪个页面、问哪个内置助手、查哪一章。

## 排障总流程

出问题时，按这三步走通常最快：

1. **先看服务状态** —— 侧边栏「管理」→「服务状态」，看健康度评分和各服务是否在线。这里通常是第一个要看的地方。
2. **再看日志** —— 在「服务状态」的「实时日志」标签，按服务 / 级别 / 关键词筛选，定位报错行。
3. **问助手或查章节** —— 用页面内置的**运维助手**用自然语言排查，或按下表跳到相关章节。

| 现象 | 先去哪 | 相关章节 |
|------|--------|----------|
| 页面打不开 / 某个服务异常 | 「服务状态」总览 + 实时日志 | 《服务状态监控》 |
| 部署中途失败、环境找不到 | 部署机上 `nexus-cli deploy` | 《部署与升级》 |
| 登录不了 / SSO 报错 | 登录页 + 认证配置 | 《登录与 SSO》 |
| 构建 / 对话报 `AccessDeniedException` | Bedrock 控制台模型访问 | 《模型目录与接入》 |
| 备份、制品同步失败 | 部署机上 `nexus-cli` | 《配置管理》《部署与升级》 |
| Logo / 品牌改了不生效 | 品牌配置 + 强刷浏览器 | 本章「品牌与 Logo」 |

## 服务与运维

**服务起不来、页面打不开、请求报错**，多数能在「服务状态」页定位。

| 现象 | 排查方向 |
|------|----------|
| Web 界面打不开 | 确认 Frontend（Web，:3000）服务在线；未在线则在服务卡片上点「启动」，或 `nexus-cli service start --web` |
| 接口报错 / 数据加载失败 | 确认 API（:8000）在线；看「实时日志」里 API 的 ERROR 行 |
| 构建任务一直排队不执行 | 多为 Worker 未在消费；确认 Worker 在线，必要时重启 |
| 界面短时无响应 | 若刚重启过 `api`，属正常现象——API 重启期间会短暂不可用，稍等自动恢复 |
| 「基础设施连接」显示 `error` | 问题多在数据库 / 缓存 / 存储等底层依赖，而非平台服务本身；先确认这些托管服务是否可达 |

::: warning
停止服务会让相关功能**立即不可用**（例如停止 Worker 会导致构建任务停止消费），停止和重启都会记入运维告警。请在业务低峰期操作，非必要不要长时间停用关键服务。
:::

服务的启停、日志、健康度等完整说明见《服务状态监控》。

## 部署与升级

部署与升级都在**部署机**上用 `nexus-cli` 完成。常见问题：

| 现象 | 排查方向 |
|------|----------|
| 部署中途失败、留下半截资源 | 多为区域服务配额（EIP / VPC / NAT 等）不足或部署权限缺失；补齐后用**同一条命令**重新执行即可续跑，不会重复建栈 |
| 找不到某个环境的状态 | 用 `nexus-cli deploy list` 确认环境前缀，再用 `nexus-cli deploy status <前缀>` 查看 |
| 升级链接失效 | 一键升级的更新链接有有效期（默认数小时，最长 7 天），过期需请维护者重新签发 |
| 目标版本无法升级 | 过旧的版本可能不含升级所需组件，需改为重新部署 |

::: tip
升级只更新计算节点上的代码与本地配置，**数据不受影响**——数据库、缓存、对象存储都在节点之外。升级会重启服务、有短暂中断，建议在低峰期进行。
:::

完整的部署、升级、删除环境流程见《部署与升级》。

## 登录与认证

| 现象 | 排查方向 |
|------|----------|
| 忘记密码 / 首次登录 | 密码模式的默认凭证为 `admin` / `nexus`；生产环境务必在部署时改掉 |
| 启用了 SSO 但登录失败 | 确认 SSO 已在认证配置中开启、IdP 元数据地址正确、回调地址与实际域名一致 |
| SSO 登录报域名不允许 | 若配置了邮箱域名白名单，只有白名单内的域名可登录；确认用户邮箱域名在允许列表中 |
| SSO 全线不可用、急需进后台 | 密码模式凭证在启用 SSO 后仍作为后备的配置管理员保留，可用它应急登录 |

登录方式、SSO 对接与用户组分配详见《登录与 SSO》。

## 模型访问

平台的构建与对话依赖 AWS Bedrock 上的模型。**新账号首次使用前必须手动开通模型访问**，这一步 IAM 权限无法代替。

| 现象 | 排查方向 |
|------|----------|
| 构建 / 对话报 `AccessDeniedException` | 到**部署区域**的 Bedrock 控制台 → *Model access*，申请开通平台所需模型（Claude 系列），启用后重试 |
| 报错提示 `aws-marketplace:ViewSubscriptions` / `Subscribe` | 同上，目标模型尚未在账号中订阅启用 |
| 部分功能可用、部分报错 | 平台用到默认模型、轻量模型、专业模型三档，确认三档模型在部署区域都已开通 |

模型分档、区域与接入方式详见《模型目录与接入》。

## 备份、恢复与制品同步

平台的项目备份和 Agent 制品同步会用到对象存储与数据表。这些资源由 `nexus-cli init` 一次性初始化。

| 现象 | 排查方向 |
|------|----------|
| 提示对象存储桶不存在 / 数据表不存在 | 在部署机上运行 `nexus-cli init` 初始化缺失的基础设施 |
| 同步 / 备份报 `Access Denied` | 部署角色缺少对象存储或数据表的读写权限；套用平台随附的运行时 IAM 策略即可 |
| 提示找不到某个 Agent 的文件 | 确认 Agent 名称拼写正确，且该 Agent 确实存在于本环境 |
| 恢复 / 覆盖已有项目前想留后路 | 强制覆盖会**先自动创建一份安全备份**再覆盖，可放心操作 |

::: warning
删除环境时加 `--clean-data` 会连同对象存储、数据表、队列里的数据一并删除，**无法恢复**。执行前请确认数据不再需要或已另行备份。
:::

备份与制品的日常管理见《配置管理》与《部署与升级》。

## 品牌与 Logo

替换客户自定义 Logo 时，常见的是"改了配置但页面没变"——多为缓存问题。

| 现象 | 排查方向 |
|------|----------|
| 改了品牌配置但 Logo 没变 | 前端对品牌配置有缓存，切换页面不会重取。用浏览器**强制刷新**（`Cmd+Shift+R` / `Ctrl+Shift+R`）；若有 CDN / 反向代理缓存，给 Logo 地址加版本参数（如 `/logo.svg?v=2`） |
| SVG 在浏览器能打开、但页面上不显示 | SVG 内含外链字体、外链图片或内联脚本会被安全策略（CSP）拦截。改用只含矢量路径的纯 SVG |
| 只有深色模式下 Logo 看不清 | 准备一份深色背景适配的 Logo，在品牌配置中填入深色版本地址 |
| 换了 Logo，浏览器标签页图标（favicon）没变 | 标签页图标不走品牌配置，需单独替换 favicon 文件后重启 Web 服务 |

::: tip
Logo 替换后，记得检查这几处是否都已更新：桌面端左侧侧边栏、移动端顶部与抽屉菜单、登录页、Agent 备份导入对话框。
:::

::: info
替换品牌资源后需**重启 Web 服务**才能让新静态资源生效：`nexus-cli service restart --web`。接口服务会在下次读取品牌配置时自动更新，一般无需重启。
:::

## nexus-cli 快速参考

日常巡检建议优先用网页「服务状态」页——一屏看齐健康度、资源与全部服务状态。需要在服务器上操作或写进运维脚本时，再用 `nexus-cli`：

```bash
nexus-cli service status              # 查看所有服务状态
nexus-cli service logs --api          # 查看指定服务日志
nexus-cli service logs -f             # 实时跟踪日志（Ctrl+C 退出）
nexus-cli service restart --api       # 重启指定服务
nexus-cli service stop --web          # 停止指定服务
nexus-cli service start --web         # 启动指定服务
```

服务标识可用 `--api`、`--worker`、`--web`、`--mcp` 等；命令行操作与网页按钮效果一致。所有命令加 `--lang zh` 可切换中文提示。

::: tip
`nexus-cli service` 系列命令要在应用节点上执行。MCP 服务的启停与令牌管理详见《MCP 服务管理》。
:::

## 内置助手怎么帮你排障

管理页面都配有随身 AI 助手，遇到问题不必先翻文档，可以直接用自然语言问：

| 助手 | 在哪里打开 | 能问什么 | 护栏 |
|------|------------|----------|------|
| **运维助手** | 「服务状态」页右下角浮动按钮 | 哪个服务不正常、最近谁在刷 ERROR、某服务启动失败怎么排查 | 只做**只读诊断**，不会替你重启 / 停止服务 |
| **配置助手** | 「配置管理」页 | 某个配置项作用、改哪个能生效、是否需要重启 | 涉及改动仍需你确认后执行 |
| **审计助手** | 「审计日志」页 | 谁在什么时候做了什么、按人 / 时间 / 操作检索 | 只读检索，不改数据 |

<!-- SCREENSHOT: ops -->

::: warning
运维助手只做诊断——查状态、读日志、给排查思路。它**不会**替你重启或停止服务；这些有风险的操作仍需你在服务卡片上手动点按钮并二次确认。
:::

内置助手的完整能力见《内置 AI 助手（管理员）》。

## 注意事项

- 出问题先看「服务状态」的健康度和服务列表，再用「实时日志」定位报错，必要时问运维助手。
- 重启 / 停止关键服务尽量安排在业务低峰期，`api` 重启期间会短暂不可用。
- 新账号首次使用前，务必在部署区域的 Bedrock 控制台手动开通模型访问，否则构建与对话会报 `AccessDeniedException`。
- 生产环境务必修改密码模式的默认凭证（`admin` / `nexus`）。
- 删除环境的 `--clean-data`、备份的源删除等选项**不可恢复**，执行前反复确认。
- 「基础设施连接」显示 `error` 时，说明问题可能出在底层托管依赖，而非平台服务本身。
