# 审计追踪

审计追踪页把平台上「谁、在什么时间、对什么做了什么、结果如何」的操作记录集中到一个界面：既能看趋势仪表盘，也能按多维条件检索明细、导出留存，还能订阅邮件通知、让 AI 审计助手帮你查问题和出合规报告。审计记录**防篡改**，可随时校验完整性。

::: info
本页仅管理员可见。审计范围覆盖登录、配置改动、用户管理、越权拦截、审计导出等平台管理动作；连「导出审计」「生成合规报告」这类操作本身也会被记入审计。
:::

### 典型场景

有用户反馈自己的 Agent 被人改动了，但不知道是谁、什么时候改的。你打开「审计追踪」→「日志」，在搜索框输入该 Agent 的名称，立刻就能看到谁在什么时间做了什么修改、改了哪些字段。如果筛选条件不好拼，也可以点右上角「Nexus 助手」，用自然语言问一句「最近一周谁修改了 XX Agent？」，助手直接返回操作人、时间和变更内容摘要。

## 打开审计追踪

侧边栏「设置」→「审计追踪」，或直接访问 `/settings/audit`。

页面顶部有三个页签，右上角是浮动的「Nexus 助手」按钮（AI 审计助手）：

| 页签 | 用途 |
|------|------|
| **仪表盘** | 按时间范围看审计概览：动作分布、成功率、异常提示、完整性校验 |
| **日志** | 多维筛选检索审计明细，展开看改动详情，导出 CSV / JSON |
| **订阅通知** | 用邮箱订阅审计事件通知与合规报告投递 |

## 仪表盘

用途：一眼看清所选时间段内的审计概况与是否存在异常苗头。

1. 进入「仪表盘」页签（默认页签）。
2. 用顶部时间范围按钮切换统计区间：「近 7 天」「近 30 天」「近 90 天」。
3. 查看图表与提示：
   - **动作分布**饼图（按类型聚合，如 `auth` / `user` / `config`）。
   - **成功率**饼图（成功 / 失败 / 拒绝的占比）。
   - **异常提示卡**，例如「本期 N 次非工作时间操作」——提醒你留意非工作时段的敏感操作。
4. 点图表中的某一类，可直接带着该筛选条件跳到「日志」页签查看对应明细。

### 完整性校验

审计记录以**防篡改**方式串接存储。点仪表盘上的「重新校验」按钮，平台会重新核对整条审计链是否完整、有无被删改，并给出校验结果（已检查条数 / 总数，以及第一处异常的位置，如果有）。

::: warning
如果校验结果提示链不完整，说明审计记录可能被改动或缺失，应立即排查并保留现场，不要继续覆盖操作。
:::

## 日志检索

用途：按人、动作、资源、结果、时间、关键词等多维条件精确定位某次操作。

入口：「审计追踪」→「日志」页签。


### 筛选条件

筛选栏支持以下条件，改动后自动重新查询：

| 筛选项 | 说明 |
|--------|------|
| **搜索框** | 关键词匹配（覆盖动作、邮箱、详情等文本） |
| **操作类型** | 按具体动作过滤，如 `auth:login`、`config:update`、`config:rollback`、`config:import`、`user:create`、`user:change_role`、`user:change_status`、`user:change_policies`、`user:delete`、`user:reset_password`、`access:denied`、`audit:export` |
| **资源类型** | `config` / `user` / `auth` / `audit` |
| **结果** | 成功 / 失败 / 拒绝 |
| **日期范围** | 起始日期 → 结束日期 |

设置了任意筛选条件后，栏内出现「清除」按钮，一键重置所有条件。

### 表格与明细

日志以表格呈现，列包括：

| 列 | 内容 |
|----|------|
| **时间** | 操作发生的时间 |
| **操作人** | 用户名与邮箱 |
| **操作** | 动作标签（按类型着色） |
| **资源** | 资源类型 / 资源 ID |
| **结果** | 成功 / 失败 / 拒绝 |
| **IP** | 来源 IP 地址 |

1. 点带展开箭头的行，可展开查看该条的详细信息：
   - **详情**文本描述；
   - **改动明细**：配置 / 用户类操作会逐项列出「字段：旧值 → 新值」；
   - **原因**（如有）；
   - **请求 ID**（便于跨系统追溯）。
2. 列表底部显示当前已加载条数；若还有更多，点「加载更多」继续翻页。

## 导出留存

用途：把当前筛选范围内的审计记录导出，用于归档、离线分析或合规提交。

1. 在「日志」页签设置好筛选条件（导出会沿用当前筛选）。
2. 点筛选栏右侧的「导出」按钮，从下拉里选：
   - 「导出为 CSV」——扁平表格，改动明细会合并成一列文本，适合表格软件查看。
   - 「导出为 JSON」——结构化数据，适合程序处理。

导出的字段包含时间、操作人邮箱 / 用户名、动作、资源类型 / ID、结果、IP、请求 ID、原因、详情、改动明细。

::: info
导出动作本身也会被记入审计（`audit:export`），并注明导出的条数与格式。单次导出有条数上限，范围很大时请先用筛选缩小区间。
:::

## 订阅通知

用途：让相关人员通过邮箱收到审计事件通知与合规报告，无需时刻盯着页面。

入口：「审计追踪」→「订阅通知」页签。

1. 进入「订阅通知」页签，可看到当前所有邮件订阅及其**确认状态**。
2. 添加订阅：按**邮箱**、**Nexus 用户名**或**用户 ID** 添加一条订阅。
3. 系统会向该邮箱发送一封确认邮件，收件人点确认后订阅才生效（状态从待确认变为已确认）。
4. 需要停订时，在列表中移除对应订阅即可。

::: info
新增 / 移除订阅同样会被记入审计（`audit:subscribe` / `audit:unsubscribe`）。
:::

## AI 审计助手

用途：用自然语言查审计、做区间总结、一键生成合规报告，不必手动拼筛选条件。

入口：审计页右上角浮动的「Nexus 助手」按钮。面板可在「右侧停靠」与「居中大窗」两种形态间切换。


### 问答

在输入框直接用自然语言提问，助手会**基于当前筛选范围**在后台取数并流式作答。面板给了几个常见问题作为起点：

- 这段时间谁改了配置？
- 有没有失败登录或越权尝试？
- 哪个用户操作最频繁？

回答通常是结构化小结（计数、涉及的用户与 IP、时间点罗列、异常判断，例如「均无失败记录，IP 段一致，暂未见异常」）。回答里可能带一个**跳转按钮**（如「查看今日登录记录」），点它会带着对应筛选条件跳到「日志」页签。

### 区间总结与合规报告

面板顶部有三个动作按钮，**范围跟随当前筛选条件**：

| 按钮 | 作用 |
|------|------|
| **区间总结** | 对所选时间段内的审计活动生成一段流式文字总结 |
| **生成合规报告** | 生成一份结构化的合规报告（便于归档留存），生成动作本身也会被记入审计 |
| **发送到 SNS** | 把生成的合规报告投递到审计通知邮件订阅者 |

::: tip
先在「日志」或「仪表盘」里把时间范围、动作类型等筛选条件设好，再让助手做「区间总结」或「生成合规报告」，结果就会精确对准你关心的范围。
:::

::: warning
AI 审计助手只做查询、总结与报告，**不会删改任何审计记录**；审计数据全部在服务端按范围读取，不受助手影响。
:::

## 注意事项

- 审计仅管理员可见，且导出、生成报告等操作本身都会留痕——这是设计如此，便于追责。
- 定期用「重新校验」确认审计链完整；一旦提示异常，先保留现场再排查。
- 导出范围很大时先用筛选缩小区间，避免触及单次导出上限。
- 订阅需收件人点确认邮件后才生效，添加后记得跟进确认状态。
- 拿不准怎么查，先问 AI 审计助手，用它给的跳转按钮进到明细列表。
