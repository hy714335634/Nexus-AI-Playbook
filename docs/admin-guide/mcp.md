# MCP 服务管理

MCP（Model Context Protocol）服务管理页让你集中登记外部 MCP 服务器，把它们提供的工具接入平台，供 Agent 在运行时调用。你可以添加、导入、启用/禁用、测试连接、查看工具，并按作用域（共享 / 私有）控制谁能看到、谁能用。

MCP 在平台里有两个方向：

- **作为客户端接入外部 MCP 服务**：把第三方 MCP 服务器（如 AWS 官方 MCP 服务）登记进来，Agent 就能使用它们的工具。这是本页的主要功能。
- **作为服务端对外暴露平台 Agent**：平台还内置一个对外 MCP 服务端，把「运行中」的 Agent 以 MCP 工具形式提供给外部 MCP 客户端（如支持 MCP 的桌面应用 / IDE）。见文末「把平台 Agent 暴露为 MCP 服务」。

## 打开 MCP 服务管理

侧边栏「能力中心」→ 点击「MCP 服务」卡片的「进入管理」，或直接访问 `/ability/mcp`。页面顶部导航还可切换到同属能力中心的「工具」「技能」。

![ability-mcp](/images/ability-mcp.png)

## 界面速览

页面标题为「MCP 服务器管理」，右上角有两个入口：

- **添加服务器** — 手动填写或粘贴配置新增一个 MCP 服务器
- **导入配置** — 粘贴一段配置批量导入

主区域是服务器列表，提供：

- **搜索框** — 按服务器名称、命令、URL 检索
- **作用域下拉** — 全部作用域 / 共享 / 私有
- **传输类型分组标签** — 按 STDIO / SSE / HTTP 分组展示，每组带数量徽标
- **统计** — 服务器总数、已启用数、已禁用数

每个服务器以卡片呈现，卡片上的操作按钮包括：**测试连接**、**查看工具**、**编辑**、**启用 / 禁用**、**删除**。

### 内置服务器

平台预置了一批可直接启用的 MCP 服务器，首次启动时会同步进来（仅新增、不覆盖你的改动）。常见的有：

| 服务器 | 用途 | 默认状态 |
|--------|------|----------|
| `awslabs.core-mcp-server` | AWS 核心能力 | 已启用 |
| `awslabs.aws-pricing-mcp-server` | AWS 价格查询 | 已启用 |
| `awslabs.aws-api-mcp-server` | AWS API 调用 | 已启用 |
| `strands-agents` | Strands Agents 工具 | 已启用 |

> 列表中还可能出现用于演示的示例服务器（如 `test-server`、`disabled-server`），默认处于禁用状态。

## 传输类型

添加服务器时需选择传输类型，不同类型要求填的字段不同：

| 传输类型 | 说明 | 必填字段 |
|----------|------|----------|
| **STDIO** | 以本地子进程方式运行的 MCP 服务器（如 `uvx` / `npx` 启动的包） | 命令（`command`）；可选参数、环境变量 |
| **SSE** | 通过 Server-Sent Events 连接的远程服务器 | URL；可选请求头 |
| **HTTP** | 通过 Streamable HTTP 连接的远程服务器 | URL；可选请求头 |

::: info
URL 里含 `/sse` 或以 `sse://` 开头会被识别为 SSE，其余按 HTTP 处理。STDIO 服务器要求所填命令在服务器上可执行——命令不存在时，该服务器会被跳过（不影响 Agent 使用其余工具）。
:::

## 作用域与可见性

每个服务器有一个作用域：

- **共享（shared）** — 全平台可见、可用；修改 / 删除仍需拥有者或编辑权限。
- **私有（private）** — 只有创建者本人及被显式分享的人可见。

::: info
管理员可以看到并管理所有 MCP 服务器；非管理员只能看到共享服务器、自己创建的，以及被分享或按资源组可见的那些。相关操作受工具类权限（查看 / 创建 / 修改 / 删除）约束。
:::

## 添加服务器（手动填写）

1. 点右上角「添加服务器」，打开「添加 MCP 服务器」对话框。
2. 顶部保持在「手动填写」标签。
3. 按下表填写字段：

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| **服务器名称** | 全局唯一的名称，如 `aws-docs` | 必填 |
| **传输类型** | STDIO / SSE / HTTP 三选一 | 必填 |
| **命令** | STDIO 专用，如 `uvx`、`npx`、`python` | STDIO 必填 |
| **参数** | STDIO 专用，多个参数用空格分隔 | 可选 |
| **URL** | SSE / HTTP 专用的服务器地址 | SSE/HTTP 必填 |
| **请求头** | SSE / HTTP 专用，动态添加 Key/Value 对（如鉴权头） | 可选 |
| **环境变量** | 动态添加 KEY/value 对，点「+ 添加环境变量」 | 可选 |
| **描述** | 服务器功能说明 | 可选 |
| **作用域** | 共享 / 私有 | 必填，默认共享 |

4. 必填项填全后，底部「添加服务器」按钮才可点击。点它保存。

## 粘贴 / 导入配置

不想逐字段填，可用「粘贴配置」标签或右上角「导入配置」直接贴一段配置，平台会自动识别格式：

| 格式 | 示例 |
|------|------|
| **JSON（Cursor/Kiro 风格）** | `{ "mcpServers": { "my-server": { "command": "uvx", "args": ["my-package@latest"] } } }` |
| **命令行** | `uvx awslabs.aws-documentation-mcp-server@latest` |
| **URL** | `http://localhost:3000/sse` |

对话框里提供三个示例药丸（Cursor JSON / npx·uvx 命令 / SSE·HTTP URL），点一下即可把示例填入。导入时同样可选择作用域。JSON 里的 `autoApprove` 会作为自动批准的工具列表一并导入。


## 管理已有服务器

在每个服务器卡片上：

- **测试连接** — 尝试连接该服务器并拉取工具列表，返回成功的工具数量或错误信息。连接超时会明确提示（默认约 30 秒）。用它在启用前确认服务器可达。
- **查看工具** — 列出该服务器提供的工具，每个工具展开后可看到名称、描述与参数（输入 schema）。
- **编辑** — 修改传输类型、命令 / URL、环境变量、请求头、描述、作用域等（名称不可改）。
- **启用 / 禁用** — 禁用后该服务器不会被 Agent 使用，但配置保留；随时可重新启用。
- **删除** — 移除该服务器配置，并清理它的所有分享记录。删除不可撤销。

服务器还可通过卡片的「更多」菜单**分享**给他人或**移动到文件夹**归类。

::: warning
删除是不可恢复的操作，且会一并清除该服务器的分享。删除前先确认没有 Agent 正依赖它——可先用「禁用」观察一段时间，确认无影响再删除。
:::

## 把平台 Agent 暴露为 MCP 服务

除了接入外部工具，平台还内置一个对外的 MCP 服务端，把平台上处于「运行中」的 Agent 以 MCP 工具形式暴露给外部 MCP 客户端。每个 Agent 对应一个工具，接受 `query` 参数并返回 Agent 的文本响应。

| 项目 | 说明 |
|------|------|
| **端口** | 默认 `9000`，可用环境变量 `NEXUS_MCP_PORT` 修改 |
| **访问地址** | `http://localhost:<端口>/mcp` |
| **安全 Token** | 用环境变量 `NEXUS_MCP_TOKEN` 指定；未指定时启动会自动生成并打印到控制台 |
| **健康检查** | `/health`、`/healthz` 端点无需鉴权 |

外部客户端需在请求头带上 `Authorization: Bearer &lt;token&gt;`，配置示例：

```json
{
  "mcpServers": {
    "nexus-ai": {
      "url": "http://localhost:9000/mcp",
      "headers": {
        "Authorization": "Bearer <你的 Token>"
      }
    }
  }
}
```

平台上的 Agent 发生增减后，外部客户端可调用内置的 `refresh_agents` 工具刷新可用 Agent 列表，无需重连。

::: info
只有状态为「运行中」的 Agent 才会被暴露为工具。若某个 Agent 未出现在外部客户端里，先确认它已上线运行，再调用 `refresh_agents`。
:::

## 注意事项

- 启用一个新 MCP 服务器前，先用「测试连接」确认可达、能列出工具，避免 Agent 运行时才发现不可用。
- STDIO 类型依赖服务器上已安装对应命令（如 `uvx`）；命令缺失时该服务器会被静默跳过。远程服务器则优先考虑 SSE / HTTP。
- 共享作用域的服务器全平台可见可用，敏感或实验性的服务器建议设为私有。
- 删除会连同分享记录一起清除且不可撤销，拿不准时先禁用。
- 对外 MCP 服务端的 Token 等同访问凭证，务必妥善保管；生产环境建议用 `NEXUS_MCP_TOKEN` 显式指定而非依赖自动生成。
