# 用工具扩展 Agent

Agent 光会"说"还不够，得会"动手"。**工具**就是 Agent 的一项项本领——算数、读写文件、抓网页、生成图片、查时间、调用外部服务等等。你给 Agent 配上哪些工具，它就能替你做哪些事。这篇教你搞清楚 Agent 的本领从哪里来，怎么给它添更多本领。

::: tip 谁适合看这篇
市场、运营、分析、客服等业务同学。你只需要会用浏览器点界面，不需要任何技术背景。个别偏进阶的操作（比如接入外部工具服务器）会提示你可以找技术同事帮忙。
:::

## Agent 的本领从哪里来

Agent 能用的工具，主要有四种来源：

| 来源 | 是什么 | 你要做什么 |
| --- | --- | --- |
| **内置工具** | 平台自带、开箱即用的基础本领 | 直接选用即可 |
| **生成工具** | 你用一句话描述需求、让平台帮你造出来的工具 | 先构建，再选用 |
| **导入工具** | 你或同事从外部准备好、导进来的工具 | 先导入，再选用 |
| **MCP 服务** | 接入一个外部"工具服务器"，一次带来一整套新工具 | 先添加服务器，再选用它带来的工具 |

前三种在**工具库**里管理，本篇[后面](#自己造或导入工具)会带你去看；MCP 服务是本篇重点讲的部分。

## 打开能力中心

所有能扩展 Agent 的本领，都集中在**能力中心**里。

1. 点左侧菜单里的 **能力中心**。
2. 顶部有三个标签页：**工具** / **技能** / **MCP 服务**。

![ability-tools](/images/ability-tools.png)

- **工具**：浏览、查找、构建、导入单个工具（详见[工具库](./tools.md)）。
- **技能**：给 Agent 装上成套的技能包（详见[技能库](./skills.md)）。
- **MCP 服务**：接入外部工具服务器，一次引入一批工具。

## 内置工具能帮 Agent 做什么

平台自带了一大批开箱即用的内置工具，覆盖常见的日常场景。下面按用途分了几组，帮你快速判断需要哪类：

| 用途分类 | 能做的事 |
| --- | --- |
| 文件操作 | 读取、创建、编辑文件 |
| 网络访问 | 抓取网页、调用外部服务获取数据 |
| 多媒体 | 读图识图、生成图片、生成视频、文字转语音 |
| 知识与记忆 | 检索知识库、记住上下文信息 |
| 运行代码 | 执行代码做计算、跑数据处理 |
| 系统与环境 | 处理与运行环境相关的操作 |
| 云服务 | 与云服务交互 |
| 浏览器自动化 | 自动打开网页、点击、填写、翻页 |
| 多 Agent 协作 | 让多个 Agent 分工协作、编排流程 |
| 小工具 | 算数、查当前时间等 |

::: tip 不用记这些工具的名字
你不需要背工具清单。创建或更新 Agent 时，用日常语言把需求说清楚，平台会自动帮它挑选合适的工具。这张表只是让你心里有数——平台大致都能做哪些事。
:::

## 把工具配给 Agent

工具本身不单独运行，而是**配给 Agent 后，由它在干活时自动调用**。给 Agent 添本领有两个时机：

- **创建时**：用日常语言描述你要 Agent 做什么，平台会在构建过程中自动帮它选好需要的工具。详见[创建 Agent](./create-agent.md)。
- **创建后**：如果发现 Agent 少了某项本领，在它的详情页用一句话描述改进要求（比如"希望它还能抓取网页里的表格"），让平台帮它更新。详见[管理 Agent](./manage-agents.md)。

::: tip 我要手动一个个勾选工具吗？
一般不用。最省事的做法是把"想让它做什么"讲清楚，平台替你搭配工具。你只需要关心结果，不用关心它用了哪几个工具。
:::

## 用 MCP 服务接入更多工具

有些本领来自**外部的工具服务器**——比如某个专门查资料、连数据源、或对接某类系统的服务。把这样一台服务器接进来，就能一次性给平台添上它提供的一整套工具，之后同样可以配给 Agent 使用。

::: warning 这是偏进阶的功能
添加 MCP 服务需要一些技术信息（服务器的连接方式、启动命令等），通常由准备这台服务器的技术同事提供。如果你只是想让 Agent 多一项普通本领，用[构建工具](./tools.md#构建你自己的工具)更简单。
:::

### 查看已接入的服务器

1. 在**能力中心**顶部点 **MCP 服务** 标签页，页面标题是「MCP 服务器管理」。
2. 列表里能看到已接入的每一台服务器，以及它是**已启用**还是**已禁用**。
3. 上方有搜索框，可以按名称、命令或地址查找服务器。

![ability-mcp](/images/ability-mcp.png)

每台服务器卡片上都有一排操作按钮：

| 按钮 | 作用 |
| --- | --- |
| 测试连接 | 检查这台服务器现在是否连得通 |
| 查看工具 | 看看它提供了哪些工具 |
| 编辑 | 修改服务器的连接信息 |
| 启用 / 禁用 | 打开或暂时关闭这台服务器 |
| 删除 | 移除这台服务器 |

### 添加一台服务器

1. 在 MCP 服务页面右上角点「添加服务器」，弹出「添加 MCP 服务器」窗口。
2. 窗口上方有两种填写方式：**手动填写** 和 **粘贴配置**。如果技术同事给了你一段现成的配置，用「粘贴配置」最省事；否则用「手动填写」逐项填。
3. 手动填写时，按提示填入这些内容（具体值以技术同事提供的为准）：

| 字段 | 填什么 |
| --- | --- |
| 服务器名称 | 给这台服务器起个好记的名字，例如 `aws-docs` |
| 传输类型 | 三选一的连接方式（STDIO / SSE / HTTP），照技术同事说的选 |
| 命令 | 启动服务器用的命令 |
| 参数 | 命令后面附带的参数，多个之间用空格隔开 |
| 环境变量（可选） | 需要时按"名称 + 值"成对添加，点「+ 添加环境变量」可加多组 |
| 描述 | 一句话说明这台服务器是干什么的 |
| 作用域 | 选 **共享**（团队都能用）或 **私有**（只有你能用） |

4. 必填项填全后，「添加服务器」按钮才可点击。确认无误后点它完成添加（想放弃就点「取消」）。


添加成功后，这台服务器会出现在列表里。用「查看工具」就能看到它带来了哪些新工具，之后这些工具便可像其他工具一样配给 Agent。

::: tip 连不上怎么办？
先用服务器卡片上的「测试连接」看看是不是通的。如果连不上，多半是连接信息填错了——把配置发给提供服务器的同事核对一下，或直接请他们帮你重新填一遍。
:::

## 自己造或导入工具

内置工具和 MCP 服务都不够用时，你还可以让平台帮你**造**一个专属工具，或把现成的工具文件**导**进来：

- **构建工具**：在**工具**页面点「构建工具」，用一句话描述你想要的工具，平台会自动造好。造好的工具出现在「生成工具」里。
- **导入工具**：在**工具**页面点「导入工具」，把现成的工具文件加进来，出现在「导入工具」里。

这两项操作的详细步骤，见[工具库](./tools.md)。

::: warning 有的工具需要"钥匙"才能用
有些导入的工具需要绑定一把**密钥**（相当于访问外部服务的钥匙）才能正常工作。如果某个工具提示"需要密钥"，请到**业务集成**里的密钥管理去绑定对应的密钥。详见[集成中心](./integration-center.md)。
:::

## 常见问题

**我需要自己搞清楚 Agent 该用哪些工具吗？**
不用。最省事的做法是把"想让 Agent 做什么"讲清楚，平台会自动帮它挑选和搭配工具。这篇里的分类表只是帮你了解平台大致能做哪些事。

**内置工具、MCP 服务，我该用哪个？**
先看内置工具够不够——绝大多数常见需求它都能覆盖，且开箱即用。只有当你需要接入某台特定的外部服务器时，才用得上 MCP 服务，而那通常需要技术同事提供连接信息。

**MCP 服务器为什么连不上？**
用服务器卡片上的「测试连接」检查。连不上一般是连接信息（命令、参数、地址等）填得不对，把配置交给提供服务器的同事核对即可。

**接进来的工具会一直在吗？**
会。已添加的 MCP 服务器和造好的工具都会保留下来，下次登录还在，可以反复配给不同的 Agent 使用。
