# 创建 Agent

Agent 是你的专属智能助手。你只要用日常语言描述"想让它帮你做什么"，系统就会自动帮你把它设计、开发并上线，全程不需要写任何代码。

本篇教你从零创建一个 Agent，并看着它一步步构建完成。

::: tip 谁适合看这篇
市场、运营、分析、客服等业务同学。你只需要会用浏览器点界面，不需要任何技术背景。
:::

## 两种创建方式

系统提供两种创建方式，先看看哪种适合你：

| 方式 | 适合场景 | 特点 |
| --- | --- | --- |
| **快速创建** | 需求已经想清楚了 | 直接把需求写出来，立即开始构建 |
| **引导创建** | 还没完全想好 | 系统先问你几个问题，帮你把需求补充完整，再开始构建 |

如果你是第一次使用，建议先用**快速创建**体验一遍；等需求比较复杂时，再用**引导创建**。

## 在哪里开始

打开创建页面的入口有好几个，任选其一：

1. 侧边栏底部的蓝色「创建 Agent」按钮
2. 左侧菜单点「Agents」进入列表页，再点右上角的「+ 创建 Agent」
3. 首页顶部那张「从想法到 Agent 自动化构建」卡片，可以直接在里面输入需求

![agents-list](/images/agents-list.png)

## 方式一：快速创建

最省事的方式，直接在首页卡片里就能完成。

1. 回到首页（点侧边栏「My Home」或左上角 Logo）。
2. 找到顶部的「从想法到 Agent 自动化构建」卡片。
3. 在文本框里描述你想要的 Agent。描述越具体越好，比如：

   > 创建一个中英互译助手：输入中文输出英文，输入英文输出中文，保持原文语气。

4. 点右侧的「构建」按钮（也可以按回车）。
5. 页面会自动跳转到**构建进度页**，你就能看着它一步步做出来了（见下方[看着 Agent 构建完成](#看着-agent-构建完成)）。

![quick-create](/images/quick-create.png)

::: tip 需要给 Agent 起名字吗
不用。快速创建会自动从你的描述里提取一个名字（例如上面的例子会被命名为"中英互译助手"）。构建完成后你也可以再改。
:::

### 也可以在创建页里选"快速创建"

如果你是从「创建 Agent」按钮进来的，会先看到两张卡片，点左边那张：

- **快速创建**（⚡ 图标）——"直接输入需求，跳过清理，立即开始构建 Agent。适合需求明确的场景。"

点进去后同样是填写需求、点构建，流程和首页一样。

## 方式二：引导创建

如果你还没想清楚细节，让系统来帮你补齐。

1. 通过任意入口进入创建页面。
2. 在两张卡片里点右边那张：
   - **引导创建**（💬 图标）——"AI 会分析需求中的模糊点，通过几轮问答帮你完善需求，生成更精确的 Agent。"
3. 先用一句话写下你的大致想法（至少写十几个字，太短系统会提示你补充）。
4. 提交后，系统会分析你的描述，找出里面模糊或缺失的地方，然后**分几轮向你提问**。问题有的是单选、有的是多选、有的让你自己填。
5. 逐题回答，答完点继续，进入下一轮。页面上方会显示"第几轮 / 共几轮"，让你知道还剩多少。
6. 问答结束后，系统会把你的回答整理成一份**更完整的需求**给你确认。
7. 确认无误后点开始构建，同样进入构建进度页。

![guided-create](/images/guided-create.png)

::: tip 大概要问几轮
通常最多三轮。每轮的问题都是为了让最终的 Agent 更贴合你的需要，认真回答会得到更好的结果。
:::

## 给需求加上图片或文档（可选）

如果你有现成的资料（比如一张示例截图、一份说明文档、一个数据表格），可以把它一起交给系统，帮助它更准确地理解你的需求。

1. 在需求输入区找到「添加附件」（回形针图标）。
2. 选择要上传的文件，支持常见的图片、文档、表格等格式，一次最多 10 个。
3. 上传后系统会**自动读取文件内容**，每个文件旁会显示"解析中 → 已解析"。
4. 等所有文件都显示"已解析"，再点构建。

::: warning 注意
文件还在"解析中"时点构建，系统会提示你稍等。等全部解析完成再提交即可。如果某个文件显示"解析失败"，把它移除后重试或换一个文件。
:::

## 看着 Agent 构建完成

提交后，页面会跳到该 Agent 的**构建进度页**。这里能实时看到系统正在做什么。

![project-detail-stages](/images/project-detail-stages.png)

页面上你会看到：

- **顶部**：Agent 名称，以及「返回」「暂停」「删除」三个按钮。
- **概况卡片**：本次构建的总耗时、用量等统计信息。
- **构建阶段时间轴**：一条纵向的流程，列出每个阶段和它的状态。

每个阶段前面的图标告诉你进度：

| 图标 | 含义 |
| --- | --- |
| ✅ | 该阶段已完成 |
| 🔄 | 该阶段正在进行 |
| ⏳ | 该阶段还在排队等待 |

系统会从"读懂你的需求"开始，依次完成需求分析、方案设计，最后把 Agent 上线，整个过程全自动进行。

::: tip 构建要等多久？
一般 10 到 40 分钟，取决于需求的复杂程度。这段时间你可以放心去忙别的——构建在后台进行，随时回到这个页面就能看到最新进度。
:::

::: warning 中途不用一直盯着
你可以离开这个页面。之后从首页的"构建进度"区域，或从 Agents 列表，都能重新找到它。构建完成后，这个 Agent 就会出现在你的 Agents 列表里，可以直接开始对话使用。
:::

## 构建完成之后

当所有阶段都变成 ✅，你的 Agent 就做好了。接下来你可以：

- 到 **Agents 列表**里找到它，点开查看详情。
- 直接和它**对话**，试试效果。
- 如果效果不理想，可以用一句话描述改进要求，让系统帮你更新它。

## 完整案例：造一个"云成本优化助手"

光看步骤可能还不够具体。下面用一个真实场景，带你完整走一遍——这个例子需要**专业知识（云计费）+ 特定输入（账单）+ 固定产出（优化报告）**，正是适合交给 Agent 的那类需求。

**背景**：运维同学每月要看一堆 AWS 账单，人工找哪里花超了、能怎么省，费时又容易漏。

**第一步——写需求**（快速创建，把"给谁用/做什么/要什么结果"说全）：

> 创建一个云成本优化助手：我会粘贴或描述 AWS 月度账单，你负责分析成本结构（按服务、按用途分类），找出可优化的项目并给出具体建议（如实例降配、预留实例、闲置资源清理），最后对比优化前后的预计费用。用中文输出，结论放最前面。

**第二步——为什么这样写有效**：

| 描述里的这句 | 起的作用 |
|--------------|----------|
| "分析成本结构（按服务、按用途分类）" | 告诉它**怎么拆解**，而不只是"看看账单" |
| "给出具体建议（如实例降配…）" | 给了**方向和例子**，产出更落地 |
| "对比优化前后的预计费用" | 规定了**产出物形态**，每次都有可量化结论 |
| "结论放最前面" | 约定了**排版**，方便你一眼看重点 |

**第三步——用起来**：构建完成后，在对话里粘贴一段账单明细，它就会按你规定的格式产出分析。不满意就追一句"预留实例这块再展开讲讲"，它会就地细化。

::: tip 举一反三
把上面的"AWS 账单/成本优化"换成你自己的领域，套路一样：**说清输入什么、按什么方法处理、产出什么格式**。比如"粘贴一段服务器报错日志，定位可能原因并给排查步骤""上传一份合同，按我们公司的审查清单逐条核对"。
:::

## 常见问题

::: tip 构建到一半想改需求怎么办？
等这次构建结束后，在 Agent 详情里用"更新"重新描述你的要求即可，不必删掉重来。
:::

::: tip 可以同时创建多个 Agent 吗？
可以，每个 Agent 都是独立的构建任务，互不影响。
:::

::: warning 构建失败了怎么办？
如果某个阶段显示失败，通常是需求描述不够清楚。回到创建页面，把需求写得更具体一些（要做什么、输入什么、输出什么），再创建一次。
:::
