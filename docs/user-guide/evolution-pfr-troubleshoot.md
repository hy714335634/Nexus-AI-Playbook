# 进化/PFR/故障排查

Agent 上线不是终点。上线之后你还要不断打磨它、听取反馈、遇到问题时快速定位——这三件事分别对应三个工具：

- **进化管理**：像管项目一样，把每个 Agent 的改进需求排进"迭代"里，跟踪进度直到上线。
- **迭代复盘（PFR）**：给 Agent 的每一版改动打分、留下改进建议，让下一版更好。
- **故障排查**：Agent 表现不对时，描述一下问题，系统帮你整理出处理方案。

下面分别介绍。

## 进化管理：像管项目一样管 Agent 的改进

进化管理页面把所有 Agent 的改进工作集中到一块看板上。

打开后，你会先看到一排概览数字，帮你一眼掌握全局：

| 概览指标 | 含义 |
|---------|------|
| **进行中项目** | 当前正在推进的改进项数量 |
| **即将到期** | 快到交付时间的项目数量 |
| **本周交付** | 本周计划完成的数量 |
| **风险预警** | 需要你留意、可能出问题的项目数量 |

数字下方是**泳道视图**，按阶段把每一项改进分列展示：

- **规划中** —— 已提出、还没开始动手的需求
- **执行中** —— 正在修改、构建的需求
- **验证中** —— 改完了，正在测试、灰度验证
- **已发布** —— 已经上线的版本

页面右侧还有一条**事件流**，实时记录最近发生了什么（比如某个 Agent 完成灰度、某次改动准确率提升等），方便你随时了解进展。

![evolution-progress](/images/evolution-progress.png)

::: tip 想导出一份进展汇总？
点右上角的「导出日报」，系统会帮你生成一份当天的进展报告。
:::

### 提交一个改进需求

想让某个 Agent 变得更好，先把你的想法提交成一个需求：

1. 在进化管理页面点右上角的「提交需求」。
2. 在打开的表单里填写：
   - **需求标题**（必填）：一句话说清你想改什么，例如"客服助手支持多语言"。
   - **负责人**：从下拉菜单里选一位负责人。
   - **优先级**：选"高""中"或"低"。
   - **需求描述**（必填）：把你希望达到的效果、遇到的问题写清楚，越具体越好。
3. 填好后点「提交需求」。如果还没想好，可以先点「保存草稿」，之后再回来继续。

![evolution-submit](/images/evolution-submit.png)

提交后，这条需求会出现在"规划中"泳道里，随着推进逐步移动到"执行中""验证中""已发布"。

### 跟踪进度和历史

进化管理还提供了几个视图，帮你从不同角度看清改进的进展：

| 视图 | 你能看到什么 |
|------|------------|
| **进度跟踪** | 用燃尽图、依赖关系、里程碑时间线展示整体进度 |
| **Agent 迭代** | 一张表，列出每个 Agent 当前的版本、状态、负责人和所属迭代 |
| **版本历史** | 对比不同版本之间的差异，看清每次改了什么 |
| **分析报告** | 成功率趋势、耗时分布、风险排行等统计 |

![evolution-agents](/images/evolution-agents.png)

::: tip 这些视图在攒够数据后才有内容
如果你刚开始使用，这些图表可能还是空的。随着改进需求逐步推进、积累记录，图表就会自动填上数据。
:::

## 迭代复盘（PFR）：给每次改动打分、留建议

改完一版 Agent，好不好用？迭代复盘就是让评审人给它打分、写下改进建议的地方，帮团队把每一版都往更好里推。

打开复盘工作台，你会看到：

- 顶部一张**当前 Agent 卡片**，显示它的版本号、本周被评审的次数、以及用户满意度。
- 中间是**评审队列**，列出等着复盘的改动，每条显示标题、提出人和当前状态（待评审 / 进行中）。
- 右侧是**上下文面板**，可以在三个标签间切换，帮你在打分前先了解背景：

  | 标签 | 展示内容 |
  |------|---------|
  | **对话上下文** | Agent 和用户的真实对话记录 |
  | **当前提示词** | 这一版 Agent 正在用的指令内容 |
  | **历史建议** | 上一轮复盘时留下的改进意见 |

![pfr-history](/images/pfr-history.png)

### 提交一次复盘反馈

1. 在评审队列里选中你要复盘的那一条。
2. 结合右侧上下文了解背景后，在底部填写评审：
   - **评审评分**：从下拉菜单里选一个 1-5 的分数，从"5 - 优秀"到"1 - 不通过"。
   - **改进建议**（必填）：写下具体的改进意见，例如针对提示词、工具使用或记忆策略给出建议。
3. 填好后点「提交反馈」。如果还没写完，可以先点「保存草稿」。
4. 提交成功后，页面会提示反馈已提交。

::: warning 改进建议不能留空
"改进建议"是必填项。就算打了高分，也请写一句你的看法，方便下一版参考。
:::

### 查看复盘历史

想回顾过往的复盘记录：

1. 进入"复盘历史"。
2. 页面上有一张表，列出每次复盘的编号、对应 Agent、评审人、评分、状态和日期。
3. 你可以用顶部的搜索框按 Agent 或评审人查找，也可以用"状态"下拉菜单筛选（全部状态 / 已合入 / 待复盘）。
4. 需要把记录发给别人时，点「导出 CSV」，会生成一份可以用表格软件打开的文件。

![pfr-history](/images/pfr-history.png)

## 故障排查：描述问题，拿到处理方案

当某个 Agent 表现不对劲——回答错了、卡住了、结果不符合预期——故障排查工具能帮你快速理清思路、拿到一份处理方案。

![troubleshoot-analysis-page](/images/troubleshoot-analysis-page.png)

打开页面后：

1. 在中间的大输入框里，用日常语言把遇到的问题描述清楚，例如"客服助手最近经常答非所问"。
2. 输入框下方有几张**问题分类卡片**，帮你快速对号入座。点一下感兴趣的分类，可以展开查看对应的建议处理流程。
3. 描述好之后，点「生成方案」，系统会根据你的描述整理出一套排查和处理建议。
4. 如果你只是想先把问题记下来、稍后再处理，可以点「记录问题」。

页面还会显示几个概览数字，帮你了解整体排障情况：

| 概览指标 | 含义 |
|---------|------|
| **今日已解决** | 今天已经处理完的问题数量 |
| **待处理告警** | 还没处理的告警数量 |
| **平均耗时** | 平均处理一个问题需要多久 |
| **自动修复率** | 系统能自动修复的问题占比 |

### 分步骤深入排查

页面底部的**快速导航**把一次完整的排查拆成几个阶段——从分析问题、复现问题，到审查、修复、再到跟踪验证。点对应的入口就能进入某个阶段深入处理。

::: tip 部分阶段仍在完善中
分步骤的详细排查页面正在逐步开放，有些入口点进去可能还是空白。日常使用时，先用主页面的「生成方案」拿到整体建议即可。
:::

## 常见问题

::: tip 进化管理和迭代复盘有什么区别？
简单说：**进化管理**管的是"要改哪些、改到哪一步了"，像项目看板；**迭代复盘**管的是"这次改得好不好、下次怎么更好"，是打分和留建议的环节。两者配合，让 Agent 一版比一版好。
:::

::: tip 提交的需求多久能上线？
这取决于需求的复杂度和负责人的排期。你可以在进化管理的泳道视图里随时看到它走到了哪一步（规划中 → 执行中 → 验证中 → 已发布）。
:::

::: warning 打分前先看一眼上下文
复盘打分时，右侧的"对话上下文""当前提示词""历史建议"能帮你做出更准确的判断。别只凭印象打分，先看看实际发生了什么。
:::
