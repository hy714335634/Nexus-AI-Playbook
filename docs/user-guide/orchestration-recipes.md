# 从目标到方案：能力编排配方

前面的章节教你用好**单个功能**（创建 Agent、对话、发布应用……）。但你脑子里的想法，往往是一个**目标**，而不是一个功能——比如"我想让 AI 帮我在服务器上跑一套检查并出报告"、"我想要一个能持续盯着某个数据、有情况就通知我的助手"。

这一篇教你一种思路：**把一个目标，拆成"先准备什么、再按什么顺序用哪些能力"的组合方案**。想不清楚怎么下手时，回到这一篇，或者直接去问[手册助手](../index.md#手册助手)——它会照着这里的配方，给你一条从目标到落地的路径。

::: tip 这一篇怎么用
不用从头读。找到最像你目标的那个配方，照着走；你的目标是它的变体，就照着改。每个配方都标了"依赖哪些章节"，点进去看具体操作。
:::

## 先想清楚三件事

拿到一个目标，先问自己：

1. **需要一个什么样的 Agent？** 是通用助手够用，还是需要一个懂特定领域、带专门工具的专家 Agent？
2. **它要在哪里、对什么东西干活？** 只在对话里回答问题，还是要去操作你的文件、你的服务器、你的业务数据？
3. **产出物是什么？** 一段回答、一份报告文件、一个能分享的网页应用、还是一个持续运行的自动任务？

想清这三点，下面的配方就能对号入座。

## 配方一：让 Agent 在服务器上执行任务并出报告

**典型目标**：
- "帮我对指定的内部应用做一次安全检查，生成报告"（授权范围内的安全测试、合规巡检）
- "定期登录服务器收集日志、分析异常、汇总成报告"
- "在测试机上按我给的步骤装环境、跑一套验证"

::: warning 授权前提
凡是"登录服务器执行操作"类任务——尤其是安全测试、渗透测试、漏洞扫描——**只能对你本人拥有或已获得书面授权的系统进行**。开始前确认你的授权范围，并把范围作为约束告诉 Agent（见第 4 步）。对未授权系统的探测在很多地区是违法的，平台也不支持。
:::

**编排路径**：

1. **构建一个领域专家 Agent**。用[创建 Agent](./create-agent.md)，把需求描述清楚——例如"一个安全测试助手，能对我授权的 Web 应用做标准安全检查（配置核查、常见弱点排查），并按行业规范整理成结构化报告"。说清它的**职责范围**和**要产出的报告格式**，平台会自动为它设计流程、配好合适的工具。
2. **把 Agent 连到目标服务器**。用 **Bridge**（见[连接服务器执行任务](./bridge-server.md)）建立一条到目标服务器的连接。服务器在内网或防火墙后时，用 **server 模式**——由服务器主动连回平台，你不用开放入站端口。
3. **给 Agent 划定规范约束**。在连接和对话里明确告诉它：只在授权目标上操作、允许用哪些工具/命令、禁止哪些危险动作、遇到高风险操作先暂停问你。Bridge 侧也有命令约束可作为兜底。
4. **对话驱动执行**。在[对话](./chat.md)里让 Agent 分步执行：它经 Bridge 在服务器上按你的约束跑检查，过程可见、可随时[停止](./chat.md#停止生成)。
5. **产出报告**。让它把结果整理成报告，存进对话的工作空间；你从[文件管理](./chat.md)下载。
6. **（可选）沉淀复用**。把这个 Agent 用[发布第一个应用](./publish-first-app.md)包成应用，或把它做的检查流程存成[技能](./skills.md)，下次一键复用。

**依赖章节**：创建 Agent · 连接服务器执行任务 · 对话 · 工具库 · 发布应用

## 配方二：构建一个专业领域 Agent 并持续打磨

**典型目标**："我要一个懂我们行业/我们业务的专家助手"（法务合同审查、生信数据分析、财务风控……）。

**编排路径**：

1. **引导创建**打底：用[创建 Agent](./create-agent.md)的**引导创建**模式，AI 会就模糊点反问你几轮，帮你把专业需求描述完整，比一次性写更精准。
2. **补齐专属能力**：领域任务常需要专门工具或知识——用[用工具扩展 Agent](./extend-agent-with-tools.md)加工具，或按[构建知识问答 Agent](./build-knowledge-qa.md)把领域资料喂给它。
3. **试用—迭代**：在[对话](./chat.md)里用真实案例测，不满意就调。构建出的应用还能用一句话持续改进（见[应用中心](./app-center.md)的版本更新）。
4. **团队共享**：用[资源组与共享](./resource-groups-sharing.md)把它分享给同事，或发布成应用。

**依赖章节**：创建 Agent · 用工具扩展 Agent · 构建知识问答 Agent · 对话 · 资源组与共享

## 配方三：让一件事自动定时发生

**典型目标**："每天早上自动汇总昨天的数据发给我"、"盯着某个指标，异常了就提醒"。

**编排路径**：

1. **先做出能完成单次任务的 Agent**（配方二）。先确保手动触发它能把这件事做好。
2. **交给事件任务**：用[事件任务](./events.md)把它设成定时（recurring）或自主（autonomous）任务，平台按时自动运行。
3. **盯结果**：在事件任务的运行记录里看每次执行情况。

**依赖章节**：创建 Agent · 事件任务 · 对话

## 配方四：把内部资料变成全员自助问答

**典型目标**："同事总来问制度/流程/产品细节，我想让他们自助查"。

**编排路径**：

1. 按[构建知识问答 Agent](./build-knowledge-qa.md)把资料喂给一个 Agent。
2. 用[发布第一个应用](./publish-first-app.md)发布成公开应用，链接发群里，同事不用登录就能问。
3. 收到反馈用一句话迭代（[应用中心](./app-center.md)版本更新）。

**依赖章节**：构建知识问答 Agent · 发布第一个应用 · 应用中心

## 想不清用哪个配方？

直接去问**手册助手**（首页导航「🤖 手册助手」），把你的目标原样告诉它——"我想让 AI 帮我做 XX"。它会判断这是单个操作还是一个需要组合的目标，给你对应的编排路径和每一步的手册出处。
