# 管理 Agent

Agent 管理页面是你查看、管理和操作所有已构建 Agent 的中心。通过左侧导航栏的 **「Agents」** 进入。

![Agent 列表](/images/agent-list.png)

## Agent 列表

### 搜索 Agent

页面顶部提供 **搜索框**，输入 Agent 名称或关键词即可快速查找。支持模糊匹配。

### 多维度筛选

Agent 列表支持多个维度的筛选，帮助你在大量 Agent 中快速定位目标：

#### 按部署类型筛选

| 筛选项 | 说明 |
|--------|------|
| **全部类型** | 显示所有 Agent |
| **本地部署 (Local)** | 运行在 Nexus-AI 服务器上的 Agent |
| **云端托管 (AgentCore)** | 部署在 AWS Bedrock AgentCore 上的 Agent |

**两种部署类型的区别：**

| 特性 | 本地部署 | 云端托管 |
|------|---------|---------|
| **运行位置** | Nexus-AI 服务器 | AWS Bedrock AgentCore |
| **适用场景** | 开发测试、内部使用、快速验证 | 生产环境、高可用要求 |
| **可扩展性** | 受限于服务器资源 | 自动扩缩容 |
| **管理方式** | 需要自行管理运行状态 | AWS 云端托管运维 |
| **切换方式** | 在 Agent 详情页操作 | 在 Agent 详情页操作 |

#### 按运行状态筛选

| 筛选项 | 说明 | 含义 |
|--------|------|------|
| **全部状态** | 显示所有状态的 Agent | — |
| **运行中** | 绿色标识 | Agent 正常运行中，可以发起对话 |
| **离线** | 灰色标识 | Agent 已停止运行，需要手动启动 |
| **异常** | 红色标识 | Agent 运行出错，需要排查 |

#### 按分类标签筛选

页面显示所有可用的 **分类标签**（如 cloud_consulting、data_analysis、medical_research 等）。这些标签由系统在构建 Agent 时根据功能自动生成。点击标签可以筛选特定类别的 Agent。

## Agent 卡片

每个 Agent 以卡片形式展示，包含关键信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| **名称** | Agent 的名称 | "医学文献研究助手" |
| **状态** | 运行状态 | 运行中（绿色）/ 离线（灰色）/ 异常（红色） |
| **版本号** | 当前版本 | "1.0"、"1.1" |
| **部署类型** | 本地部署 / 云端托管 | "local" / "agentcore" |
| **分类标签** | 功能分类 | "data_analysis"、"medical_research" |
| **调用次数** | 历史累计调用次数 | "156 次" |
| **创建时间** | Agent 创建的时间 | "17天前" |

### 卡片快捷操作

将鼠标悬停在 Agent 卡片上，会显示两个快捷按钮：

- **「查看详情」** — 进入 Agent 的完整详情页
- **「对话」** — 直接打开对话窗口，与 Agent 交互

## Agent 详情页

点击 **「查看详情」** 进入 Agent 的完整详情页面，这里展示了 Agent 的所有信息和操作入口。

![Agent 详情](/images/agent-detail.png)

### 概览指标

详情页顶部展示 Agent 的核心运行数据：

| 指标 | 说明 | 作用 |
|------|------|------|
| **调用次数** | 历史累计调用次数 | 了解 Agent 的使用频率 |
| **平均会话轮次** | 每次对话的平均交互轮数 | 反映对话的深度和复杂度 |
| **总 Token 消耗** | Agent 累计消耗的 Token 总量 | 了解资源使用情况 |
| **输入 Token** | 用户输入消耗的 Token | — |
| **输出 Token** | Agent 输出消耗的 Token | — |
| **平均调用耗时** | 每次调用的平均响应时间 | 评估 Agent 的响应速度 |

### 配置信息

| 字段 | 说明 |
|------|------|
| **Agent ID** | Agent 的唯一标识符 |
| **关联项目 ID** | 构建该 Agent 的项目标识 |
| **分类标签** | 功能分类（如 data_analysis） |
| **部署类型** | local（本地）或 agentcore（云端） |
| **创建时间** | Agent 创建的时间 |
| **最后调用时间** | 最近一次被调用的时间 |
| **代码路径** | Agent 代码文件的存储路径 |
| **提示词路径** | 系统提示词文件的存储路径 |

### 快速操作按钮

详情页右侧提供一组操作按钮：

| 按钮 | 功能 | 说明 |
|------|------|------|
| **开始对话** | 打开对话窗口 | 与 Agent 进行多轮对话测试 |
| **查看/编辑文件** | 代码编辑器 | 查看和在线修改 Agent 代码和提示词 |
| **查看项目** | 跳转关联项目 | 查看构建该 Agent 的项目详情 |
| **更新 Agent** | 增量更新 | 使用 Agent Update Workflow 基于新需求更新 |

### 代码查看和编辑

详情页提供在线的 **代码查看和编辑** 功能，以语法高亮方式展示：

| 文件类型 | 说明 | 格式 |
|----------|------|------|
| **Agent 代码** | Agent 的主程序文件 | Python (.py) |
| **工具代码** | Agent 关联的工具函数 | Python (.py) |
| **系统提示词** | 定义 Agent 行为的提示词 | YAML (.yaml) |

你可以在线编辑这些文件，修改后立即生效：

- **调整提示词** — 修改 Agent 的回复风格、行为逻辑
- **修改工具** — 修正工具函数的 bug 或调整参数
- **优化代码** — 改进 Agent 的主程序逻辑

::: warning
在线编辑代码需要一定的技术经验。如果不确定如何修改，建议使用「更新 Agent」功能通过自然语言描述修改需求。
:::

### 内嵌对话测试

详情页底部集成了对话测试区域，你可以直接在详情页内与 Agent 交互：

1. 在底部输入框输入消息
2. 查看 Agent 的实时响应
3. 支持多轮对话和文件上传
4. 对话历史会保存在会话中

### 最近会话

显示 Agent 最近的对话会话列表，可以快速回顾历史交互记录。

## Agent 操作

### 增量更新

如果你想在已有 Agent 的基础上进行修改（而不是重新构建），可以使用 **「更新 Agent」** 功能：

1. 点击详情页的 **「更新 Agent」** 按钮
2. 用自然语言描述你想要的修改，例如：
   - "增加一个导出 PDF 的功能"
   - "修改回复风格为更加正式"
   - "添加对 JSON 文件格式的支持"
3. 系统会启动 **Agent Update Workflow**，只修改需要改动的部分
4. 更新完成后 Agent 自动使用新版本

这比重新构建一个全新的 Agent 更高效，因为只需要修改有变化的部分。

### 部署管理

| 操作 | 说明 |
|------|------|
| **部署到 AgentCore** | 将本地 Agent 发布到 AWS Bedrock AgentCore 云端托管 |
| **启动 Agent** | 将离线的 Agent 重新启动 |
| **停止 Agent** | 将运行中的 Agent 暂停 |

**部署到 AgentCore 的好处：**
- 高可用性：AWS 云端托管，自动故障恢复
- 自动扩缩容：根据调用量自动调整资源
- 专业运维：由 AWS 负责运维管理

### 删除 Agent

在详情页中可以删除 Agent。删除前系统会弹出确认对话框，你可以选择：

| 选项 | 说明 |
|------|------|
| **删除本地文件** | 同时删除 Agent 在本地的代码文件和相关资源 |
| **删除云端资源** | 如果 Agent 已部署到云端，同时删除 AgentCore 上的资源 |

::: warning 删除不可撤销
删除操作不可撤销。删除后，Agent 的代码、提示词、工具和所有历史记录都将永久删除。请确认后再操作。如果只是暂时不需要，建议使用"停止"而非"删除"。
:::

## 交互网络

点击页面右上角的 **「交互网络」** 按钮，可以查看 **Agent 之间的调用关系网络图**。

这个可视化网络图展示了：
- 哪些 Agent 之间存在调用关系
- 调用的方向和频率
- Agent 之间的协作模式

这对于理解多 Agent 协作场景非常有用。

## 管理技巧

1. **善用分类标签** — 通过标签筛选可以快速找到特定领域的 Agent
2. **关注异常 Agent** — 定期检查是否有 Agent 处于异常状态
3. **监控调用数据** — 通过详情页的指标了解 Agent 的使用情况
4. **及时更新** — 当 Agent 的功能需要调整时，使用增量更新而非重新构建
5. **合理部署** — 测试阶段使用本地部署，稳定后再考虑部署到云端
