# MCP 服务器

MCP 服务器管理页面位于 **「能力工具」** 下的 **「MCP 服务器管理」** 标签页。在这里你可以管理通过 MCP 协议集成的外部工具和服务。

![MCP 服务器管理](/images/mcp.png)

## 什么是 MCP

**MCP（Model Context Protocol，模型上下文协议）** 是一种标准化的开放协议，用于连接 AI Agent 与外部工具和服务。它定义了 Agent 如何发现、调用和使用外部工具的标准方式。

### 为什么需要 MCP

传统方式下，让 Agent 使用外部工具需要逐个编写集成代码，工作量大且不通用。MCP 通过标准化的协议解决了这个问题：

```
传统方式：
  Agent → 定制代码 → AWS API
  Agent → 定制代码 → 数据库
  Agent → 定制代码 → 搜索引擎
  （每个集成都需要开发）

MCP 方式：
  Agent → MCP 协议 → MCP 服务器 A（AWS 工具）
                    → MCP 服务器 B（数据库工具）
                    → MCP 服务器 C（搜索工具）
  （一次集成，标准化复用）
```

### MCP 的工作原理

```
┌──────────┐     MCP 协议     ┌──────────────────┐
│          │  ◄──────────────►│   MCP 服务器      │
│  Agent   │   工具发现        │                  │
│          │   工具调用        │  ┌─────────────┐ │
│          │   结果返回        │  │ 工具 A       │ │
│          │                  │  │ 工具 B       │ │
│          │                  │  │ 工具 C       │ │
└──────────┘                  │  └─────────────┘ │
                              └──────────────────┘
```

1. **工具发现** — Agent 向 MCP 服务器查询可用工具列表
2. **工具调用** — 当需要使用工具时，Agent 通过 MCP 协议发送调用请求
3. **结果返回** — MCP 服务器执行工具并返回结果

### MCP 的优势

| 优势 | 说明 |
|------|------|
| **标准化** | 遵循统一的开放协议，不同来源的工具接入方式一致 |
| **即插即用** | 添加一个 MCP 服务器就能获得它提供的所有工具 |
| **动态扩展** | 随时添加或移除 MCP 服务器，Agent 的能力随之扩展或收缩 |
| **生态丰富** | 越来越多的服务提供 MCP 接口，可选工具不断增加 |

## 概览面板

页面顶部展示 4 个统计卡片，帮助你快速了解 MCP 服务器的整体状态：

| 指标 | 说明 |
|------|------|

| **已禁用** | 当前处于禁用状态的服务器数量（暂停使用） |
| **总工具数** | 所有 MCP 服务器提供的工具总数 |

## 浏览服务器

### 搜索和筛选

- **搜索框** — 按服务器名称搜索
- **分类筛选** — 按类别过滤（如 AWS 服务、其他）

### 服务器列表

服务器按 **类别分组** 显示（如 **AWS 服务**、**其他** 等），每个服务器展示：

| 字段 | 说明 | 示例 |
|------|------|------|
| **名称** | 服务器名称 | awslabs.core-mcp-server |
| **状态** | 启用（绿色）/ 禁用（灰色） | 已启用 |
| **传输类型** | 通信协议类型 | STDIO / SSE |
| **启动命令** | 服务器的启动命令 | uvx awslabs.core-mcp-server@latest |

### 传输类型说明

MCP 协议支持两种传输方式：

| 传输类型 | 全称 | 说明 | 适用场景 |
|----------|------|------|----------|
| **STDIO** | Standard Input/Output | 通过标准输入输出通信 | 本地运行的 MCP 服务器，最常见 |
| **SSE** | Server-Sent Events | 通过 HTTP 长连接通信 | 远程部署的 MCP 服务器 |

大多数 MCP 服务器使用 **STDIO** 传输类型。

### 查看服务器提供的工具

点击服务器行左侧的 **展开箭头 `>`**，可以查看该服务器提供的所有工具列表：

- 工具名称和功能描述
- 参数定义
- 这些工具也会同步出现在 [工具库](/using/tools) 的 MCP 工具分类中

### 服务器操作

每个服务器右侧提供操作按钮：

| 按钮 | 功能 | 说明 |
|------|------|------|
| **▶ 启动** | 启动或重启 | 启动服务器使其工具可用 |
| **🔗 连接** | 查看连接 | 查看服务器的连接配置和状态 |
| **⚙ 配置** | 编辑配置 | 修改服务器的配置参数 |
| **🗑 删除** | 删除服务器 | 从平台中移除该 MCP 服务器 |

## 添加 MCP 服务器

点击页面右上角的 **「+ 添加服务器」** 按钮来配置新的 MCP 服务器。

### 配置步骤

#### 步骤 1：输入基本信息

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| **服务器名称** | 易识别的名称 | 必填 |
| **传输类型** | 选择 STDIO 或 SSE | 必填 |

#### 步骤 2：配置连接信息

**对于 STDIO 类型：**

| 字段 | 说明 | 示例 |
|------|------|------|
| **启动命令** | 服务器的启动命令 | `uvx awslabs.aws-pricing-mcp-server@latest` |
| **工作目录** | 命令执行的工作目录（可选） | `/opt/mcp-servers` |

**对于 SSE 类型：**

| 字段 | 说明 | 示例 |
|------|------|------|
| **服务器 URL** | MCP 服务器的 HTTP 地址 | `http://mcp-server.example.com:8080` |
| **认证信息** | 访问凭证（如果需要） | API Key 或 Token |

#### 步骤 3：设置环境变量（可选）

部分 MCP 服务器需要配置环境变量（如 API 密钥、区域设置等）：

| 环境变量 | 示例值 | 说明 |
|----------|--------|------|
| `AWS_REGION` | `us-east-1` | AWS 区域 |
| `API_KEY` | `your-api-key` | 服务 API 密钥 |

#### 步骤 4：保存

确认所有配置信息后，点击 **「保存」** 完成添加。系统会自动尝试连接 MCP 服务器并获取其工具列表。

### 配置示例

**示例 1：AWS 定价查询服务器**

```
名称:     awslabs.aws-pricing-mcp-server
传输类型:  STDIO
启动命令:  uvx awslabs.aws-pricing-mcp-server@latest
```

提供的工具：AWS 各服务的价格查询、费用估算等

**示例 2：AWS 核心服务器**

```
名称:     awslabs.core-mcp-server
传输类型:  STDIO
启动命令:  uvx awslabs.core-mcp-server@latest
```

提供的工具：AWS 资源管理、配置查询等

## 管理服务器

### 启用 / 禁用

- **已启用的服务器** — 其工具可以被 Agent 调用
- **已禁用的服务器** — 其工具不会出现在 Agent 的可用工具列表中
- 随时可以切换状态，不需要删除和重新添加

**使用场景：**
- 临时不需要某个服务时，禁用而非删除
- 服务维护期间暂时禁用
- 测试时逐个启用来排查问题

### 查看服务器提供的工具

展开服务器后，可以查看它提供的所有工具：

| 信息 | 说明 |
|------|------|
| **工具名称** | 工具的函数名 |
| **功能描述** | 工具做什么 |
| **参数定义** | 工具需要什么输入 |

这些工具也会同步出现在 [工具库](/using/tools) 页面的 MCP 工具分类中，你可以在那里查看详情和进行测试。

## MCP 与 Agent 构建的关系

当你构建 Agent 时，如果需求涉及到外部服务（如 AWS 服务），系统会自动检查已配置的 MCP 服务器：

1. **Tools Agent** 分析需求，判断需要哪些外部服务
2. 检查已启用的 MCP 服务器是否提供对应的工具
3. 如果有，直接使用 MCP 工具（无需开发）
4. 如果没有，Tools Agent 会自行开发对应的工具函数

::: tip 提前配置 MCP 服务器
如果你经常需要 Agent 与某些外部服务交互（如 AWS），建议提前在 MCP 服务器管理页面配置好对应的服务器。这样在构建 Agent 时就能直接使用，加快构建速度。
:::

## 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 服务器无法连接 | 网络问题或命令错误 | 检查启动命令是否正确，确认网络连接正常 |
| 工具列表为空 | 服务器未正确启动 | 尝试重启服务器，查看启动日志 |
| 工具执行报错 | 缺少环境变量或权限不足 | 检查环境变量配置，确认相关服务的权限设置 |
| 添加失败 | 配置参数错误 | 核实服务器名称、传输类型和命令是否正确 |

::: info
MCP 服务器需要有对应的网络访问权限和服务凭证才能正常工作。如果服务器无法连接或工具执行失败，请联系管理员检查网络和权限配置。
:::
