# 常见问题

## 平台概念

### Nexus-AI 是什么？

Nexus-AI 是一个 **AI Agent 自动化构建平台**，采用"Agent Build Agent"理念 —— 用 8 个专业 AI Agent 协作来构建你想要的 AI Agent。你只需用自然语言描述需求，平台就能在几分钟内自动完成从需求分析、架构设计、代码开发到部署上线的全流程。

### 什么是 Agent？

Agent 是一个可以与你对话交互的 AI 助手。与普通的聊天机器人不同，Agent 拥有 **工具能力** —— 它不仅能回答问题，还能执行实际操作（如读取文件、调用 API、运行代码等）。每个 Agent 都是为特定业务场景量身构建的。

### 什么是 Builder Agent？

Builder Agent 是 Nexus-AI 平台内部的专业 AI Agent，负责构建你请求的 Agent。平台共有 8 个 Builder Agent：

| Builder Agent | 角色 | 职责 |
|--------------|------|------|
| Orchestrator | 项目经理 | 分析需求、制定计划、协调任务 |
| Requirements Agent | 产品经理 | 需求分析、智能提问、规格化 |
| Architecture Agent | 架构师 | 技术架构设计、组件规划 |
| Design Agent | 设计师 | 行为设计、交互流程定义 |
| Prompt Agent | 提示词专家 | 系统提示词编写、指令优化 |
| Tools Agent | 工具工程师 | 工具函数开发、API 集成 |
| Developer Agent | 软件工程师 | Agent 主程序代码编写 |
| DevManager Agent | 技术经理 | 代码审查、质量保证 |

详见 [构建原理](/overview/how-it-works)。

### 什么是 MCP？

MCP（Model Context Protocol，模型上下文协议）是一种标准化的开放协议，用于连接 AI Agent 与外部工具和服务。通过 MCP 服务器，Agent 可以即插即用地调用各种第三方工具。详见 [MCP 服务器](/using/mcp)。

### 什么是 AgentBase？

AgentBase 是平台随着使用不断积累的 **智能资产库**，包含已构建的 Agent、已开发的工具函数和高质量的提示词模板。新 Agent 的构建会自动从 AgentBase 中检索和复用已有资产，使得构建速度越来越快、质量越来越高。

### "Agentic AI Native" 是什么意思？

这是 Nexus-AI 的设计理念 —— 平台的每个模块、每个功能背后都可以是一个 AI Agent。整个平台本身就是由 Agent 驱动的系统，并且能够通过 Agent 实现自我进化和迭代。

## 账号相关

### 忘记密码怎么办？

联系管理员（Admin 角色用户）重置密码。管理员可以在 [用户管理](/admin/users) 页面为你设置新密码。

### 如何修改个人信息？

进入左侧导航栏的 **「系统配置」** 页面，可以修改用户名和邮箱。详见 [系统设置](/admin/settings)。

### 如何修改密码？

目前需要联系管理员在 [用户管理](/admin/users) 页面重置密码。

### 登录后自动退出是怎么回事？

系统使用 JWT 令牌进行身份验证，令牌有过期时间。过期后需要重新登录，这是正常的安全机制。

### 为什么看不到「用户管理」菜单？

「用户管理」仅对 Admin（管理员）角色可见。如果你的角色是 User（普通用户），则无法看到此菜单。如果你需要管理用户，请联系现有管理员升级你的角色。

## Agent 构建

### 快速创建和引导创建有什么区别？

| | 快速创建 | 引导创建 |
|---|---------|---------|
| **流程** | 输入需求 → 开始构建 | 输入需求 → AI 多轮提问 → 完善需求 → 开始构建 |
| **适用** | 需求明确、有经验的用户 | 需求模糊、初次使用、需求复杂 |
| **需求质量** | 取决于你的描述 | AI 帮你补全遗漏细节，通常更完整 |
| **耗时** | 更快 | 稍长但需求更精准 |

不确定选哪个时，建议使用 **引导创建** —— AI 的智能提问会帮你发现和补充你可能遗漏的需求。详见 [创建 Agent](/using/create-agent)。

### Agent 构建需要多长时间？

根据 11 个真实案例的实测数据：

| 复杂度 | 特征 | 预计时间 | 参考成本 |
|--------|------|----------|----------|
| 简单 | 6-14 个工具，单一功能领域 | 18-28 分钟 | $2.3-3.3 |
| 中等 | 12-25 个工具，多功能，需 API 集成 | 28-40 分钟 | $3.1-4.1 |
| 复杂 | 25-53 个工具，复杂逻辑，多数据源 | 40-62 分钟 | $3.3-5.1 |

**整体统计：** 平均构建时间 35.5 分钟，平均成本 $3.41/项目，最快 18 分钟即可完成，工作流成功率 100%，质量评分 9.3/10。

构建时间主要取决于需求的复杂程度和需要开发的工具数量。你不需要一直盯着页面，构建完成后会收到通知（如果开启了通知设置）。详细数据见 [构建进度](/using/build-progress)。

### 如何写出好的需求描述？

好的需求描述应该包含以下要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| 核心功能 | Agent 做什么 | "搜索论文、解析 PDF" |
| 数据来源 | 连接什么数据或服务 | "PubMed 数据库" |
| 输入格式 | 用户提供什么 | "PDF 文件、搜索关键词" |
| 输出格式 | 返回什么结果 | "APA 格式引用列表" |
| 语言要求 | 支持什么语言 | "中英文" |
| 行为约束 | 不应该做什么 | "不编造引用" |

**好的示例：**
> 创建一个医学文献研究助手，能在 PubMed 搜索论文、解析上传的 PDF 全文、提取关键数据，并按 APA 格式生成引用列表。支持中英文对话，遇到不确定的信息时明确告知。

**不太好的示例：**
> 帮我做个搜论文的东西

### 构建失败了怎么办？

1. **查看错误日志** — 在 [构建进度](/using/build-progress) 页面点击失败的阶段，查看详细错误信息
2. **分析原因** — 常见原因和解决方法：

| 失败原因 | 解决方法 |
|----------|----------|
| 需求描述不够清晰 | 使用引导创建模式，或提供更详细的描述后重新构建 |
| 需要的 API 不可用 | 确认 API 服务状态，或修改需求移除相关功能 |
| 系统临时异常 | 等待一段时间后重试 |
| 需求过于复杂 | 尝试简化需求，拆分成多个简单的 Agent |
| 资源限制 | 联系管理员调整配额 |

3. **重新构建** — 调整需求后创建新的构建项目。失败不会影响已有的 Agent 和数据。

### 可以修改已构建的 Agent 吗？

可以，有两种方式：

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| **在线编辑** | 在 Agent 详情页直接修改代码和提示词 | 小幅调整（如修改回复风格、修复工具 bug） |
| **增量更新** | 点击"更新 Agent"，用自然语言描述修改需求 | 功能变更（如增加新功能、调整业务逻辑） |

增量更新会启动 Agent Update Workflow，只修改需要改动的部分，比重新构建更高效。详见 [Agent 管理](/using/manage-agents)。

### 一次可以构建多个 Agent 吗？

可以。系统支持并行构建，你可以同时创建多个构建项目。在 [项目管理](/using/projects) 页面可以查看所有正在进行的构建任务。

### 构建中可以离开页面吗？

可以。构建过程在后台自动执行，你可以离开页面做其他事情。如果在 [系统设置](/admin/settings) 中开启了通知，构建完成或失败时会收到通知。

## 对话测试

### 为什么 Agent 的回答不准确？

可能的原因和解决方法：

| 原因 | 解决方法 |
|------|----------|
| 需求描述不够具体 | 重新构建时提供更详细的需求描述 |
| 缺少必要的工具 | 在 Agent 详情页检查工具列表，考虑使用增量更新添加工具 |
| 上下文过长 | 创建新会话重新开始 |
| 提问不够具体 | 提供更详细的问题和上下文信息 |
| 提示词需要优化 | 在 Agent 详情页编辑系统提示词 |

### 支持上传哪些格式的文件？

| 格式 | 类型 | 大小限制 |
|------|------|----------|
| **JPG / PNG** | 图片文件 | 单文件 50 MB |
| **PDF** | 文档文件 | 单文件 50 MB |
| **Excel (.xlsx)** | 电子表格 | 单文件 50 MB |
| **Word (.docx)** | 文档文件 | 单文件 50 MB |
| **CSV** | 数据文件 | 单文件 50 MB |
| **TXT** | 纯文本文件 | 单文件 50 MB |

每条消息最多可附加 **5 个文件**。

### 对话记录会保存吗？

是的，每个会话的完整对话记录都会保存。你可以在 [会话](/using/chat) 页面切换到历史会话查看之前的对话。

### Agent 的回复支持哪些格式？

Agent 的回复支持丰富的格式：
- **Markdown** — 标题、列表、表格、链接、引用
- **代码块** — 带语法高亮（支持多种编程语言）
- **Mermaid 图表** — 流程图、架构图、时序图等可视化图表

### 为什么同一个问题每次回答不一样？

这是大语言模型的正常特性。AI 模型在生成回答时存在一定的随机性，同一个问题可能有不同的表述方式和侧重点。如果需要一致性更高的回答，可以在提问时更加具体和限定。

## 工具相关

### 如何给 Agent 添加新工具？

三种方式：

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| **构建时自动生成** | 在创建 Agent 时描述工具需求 | 新建 Agent 时 |
| **增量更新** | 在 Agent 详情页使用"更新 Agent" | 给已有 Agent 添加功能 |
| **独立构建工具** | 在 [工具库](/using/tools) 点击「构建工具」 | 构建通用工具供多个 Agent 使用 |

### Agent 的工具是怎么来的？

Agent 的工具有多种来源：

| 来源 | 说明 |
|------|------|
| **内置工具** | 平台预置的基础工具（calculator、file_read 等） |
| **自动生成** | 构建 Agent 时，Tools Agent 根据需求自动开发 |
| **MCP 工具** | 通过 MCP 服务器集成的外部工具 |
| **独立构建** | 用户在工具库中单独构建的工具 |

### 什么是 MCP 服务器？如何配置？

MCP（Model Context Protocol）服务器是通过标准化协议提供工具的外部服务。配置方法：

1. 进入 **「能力工具」→「MCP 服务器管理」**
2. 点击 **「+ 添加服务器」**
3. 填写名称、传输类型（STDIO/SSE）和启动命令
4. 保存后系统自动获取工具列表

详见 [MCP 服务器](/using/mcp)。

### 如何测试一个工具是否正常工作？

在 [工具库](/using/tools) 页面：
1. 点击要测试的工具
2. 在右侧详情面板中查看参数定义
3. 在参数表单中填入测试值
4. 点击「执行」查看结果

## 部署相关

### 本地部署和云端托管有什么区别？

| 特性 | 本地部署 (Local) | 云端托管 (AgentCore) |
|------|:-:|:-:|
| **运行位置** | Nexus-AI 服务器 | AWS Bedrock AgentCore |
| **可用性** | 依赖服务器状态 | 高可用，自动故障恢复 |
| **可扩展性** | 受限于服务器资源 | 自动扩缩容 |
| **运维管理** | 需要自行管理 | AWS 托管运维 |
| **适用场景** | 开发测试、内部使用 | 生产环境、高可用场景 |
| **切换方式** | Agent 详情页操作 | Agent 详情页操作 |

### 如何将 Agent 部署到云端？

在 [Agent 详情页](/using/manage-agents) 中：
1. 点击 **「部署到 AgentCore」** 按钮
2. 按照提示确认部署配置
3. 系统自动将 Agent 部署到 AWS Bedrock AgentCore
4. 部署完成后，Agent 的部署类型会变更为 "agentcore"

### 可以从云端切换回本地吗？

可以。在 Agent 详情页中操作切换部署类型。

## 系统相关

### 系统支持哪些浏览器？

推荐使用以下浏览器的最新版本：

| 浏览器 | 最低版本 |
|--------|----------|
| Google Chrome | 90+ (推荐) |
| Microsoft Edge | 90+ |
| Mozilla Firefox | 88+ |
| Apple Safari | 14+ |

不支持 Internet Explorer。

### 数据存储在哪里？

Nexus-AI 的数据存储在 AWS 云服务上：
- **Agent 代码和工具** — 存储在 S3
- **项目和会话数据** — 存储在 DynamoDB
- **构建过程产物** — 存储在 S3

所有数据传输都经过加密保护。

### 遇到系统问题如何反馈？

1. 首先检查 [系统设置](/admin/settings) 中的 API 配置是否正确
2. 尝试刷新页面或重新登录
3. 如果问题持续，联系管理员
4. 也可以通过 [GitHub Issues](https://github.com/hy714335634/Nexus-AI/issues) 提交反馈

### 系统的安全性如何保障？

| 安全措施 | 说明 |
|----------|------|
| **JWT 认证** | 所有 API 请求都需要有效的 JWT 令牌 |
| **SSO 支持** | 支持 SAML 协议的企业级单点登录 |
| **RBAC 权限** | 基于角色的访问控制 |
| **数据加密** | 传输和存储数据加密保护 |
| **代码审查** | Agent 代码由 DevManager Agent 自动审查 |
