# 事件调度

## 这是什么

事件调度让你把 Nexus-AI 上任意一个 Agent 变成「定时任务」或「持续运行的自主任务」。你只需要指定「哪个 Agent」「用什么提示词」「什么时候跑」，平台会按计划自动触发 Agent 执行，把结果归档到独立的 S3 工作空间，并由一个轻量分析 Agent 生成简要的中文摘要。适合日报、定时抓取、周期性监控、以及让 Agent 自己规划下一步的长期任务。

## 使用场景

| 场景 | 选哪种任务类型 |
| --- | --- |
| 明天早上 8 点给我发一份本周项目总结 | **一次性任务**（one_time）：指定具体时间，执行一次即停 |
| 每个工作日 09:30 抓取最新行业资讯并整理成摘要 | **周期性任务**（recurring）：用 cron 表达式按固定节奏反复执行 |
| 让 Agent 自己持续跟进某个目标（如竞品监控、持续研究），不需要我手动安排每一次 | **自主任务**（autonomous）：Agent 自己读取历史记录、规划下次要做什么，目标达成后自动停止 |
| 给一个多 Agent 协作项目设一个定时入口 | 三种类型均可：调度只负责触发，多 Agent 会共享同一个 S3 工作空间 |
| 想跑一个"只有有新内容才通知我"的心跳任务 | 周期性 + Agent 回复 `HEARTBEAT_OK`，平台会自动静默空结果 |

## 如何使用

### 步骤 1：准备好一个 Agent

事件调度只负责"何时触发"，真正干活的是你绑定的 Agent。先在平台中创建好目标 Agent，确保它能独立完成你想要定时执行的那件事。

::: tip
Agent 原有的工具、Skill、多 Agent 协作配置都会被完整保留——事件调度只是在原提示词上叠加一段"任务类型上下文"，不会破坏 Agent 已有的 tools / skills / cowork 设置。
:::

### 步骤 2：创建事件任务

<!-- SCREENSHOT: event-scheduler-create-job -->

在事件调度页面点击「新建任务」，按类型填写：

**一次性任务**

1. 选择要触发的 Agent。
2. 填写触发时间（ISO 格式，如 `2026-05-10T09:00:00Z`）。
3. 写下触发时发送给 Agent 的提示词。
4. 保存——到点后自动执行一次，执行完自动停用。

**周期性任务**

1. 选择 Agent。
2. 填写 cron 表达式（5 字段：`分 时 日 月 周`），例如 `0 9 * * 1-5` 表示工作日每天 9:00。
3. 选择时区（IANA 名称，如 `Asia/Shanghai`；默认 `UTC`）。
4. 写下每次触发时的提示词（每次执行都用同一段）。
5. 可选：设置生效时间段（`valid_from` / `valid_until`）、最大执行次数。

**自主任务**

1. 选择 Agent。
2. 用 cron 表达式指定自主循环的节奏。
3. 写下初始提示词，描述你希望 Agent 持续推进的目标。
4. 可选：设定最大执行次数作为"硬上限保护"，防止跑飞。
5. 保存后，每次执行时 Agent 会先读取历史 `mission_log.md` 理解已做过什么，再规划本次动作；在回复末尾写 `## 任务完成` 则自动停止，写 `## 下一步计划` 则继续。

### 步骤 3：查看执行记录

<!-- SCREENSHOT: event-scheduler-task-history -->

每个任务都有独立的执行记录页，展示每一次执行（Task）的信息：

| 字段 | 含义 |
| --- | --- |
| 执行序号 | 同一任务下的第几次执行（从 1 开始） |
| 状态 | `pending`（等待中）、`running`（进行中）、`completed`（已完成）、`failed`（失败）、`skipped`（已跳过） |
| 计划时间 | 原本应该执行的时间 |
| 开始 / 完成时间 | 实际的执行起止时间 |
| 结果摘要 | 分析 Agent 自动生成的中文摘要（最多 1000 字） |
| 工作空间 | 本次执行的独立 S3 路径，Agent 生成的文件都在这里 |
| Agent 完整输出 | 可下载 `agent_response.out` 查看原始内容 |

### 步骤 4：启用、禁用、删除

- **禁用**：任务保留但不再触发，随时可再启用；已经创建但还没跑的执行记录，会在触发时因任务被禁用而跳过。
- **启用**：重新参与调度。一次性任务执行完后调度器会自动禁用。
- **删除**：同时级联删除该任务下的所有执行记录。
- **自主任务的自动停止**：当分析 Agent 判断目标已达成（Agent 回复包含 `## 任务完成` 或语义上表示收尾），调度器会自动把任务置为禁用并附带终止原因。

### 步骤 5（可选）：心跳与空结果静默

周期性 / 自主任务中，Agent 如果发现本次"没有新内容可报告"，可以直接回复 `HEARTBEAT_OK`（或 `NO_ACTION_NEEDED` / `NOTHING_TO_REPORT` / `TASK_SKIPPED`）。平台会识别这些标识并把摘要设为"无需操作"，避免用空报告刷屏。

::: info 自主任务的历史上下文
自主任务每次执行前，平台会把该任务的所有历史执行索引（编号、状态、时间、简要摘要、S3 输出路径）整理成表格注入到提示词中；Agent 可以按需用 `workspace_read_file` 读取具体某次的完整输出，再决定本次做什么。
:::

## 关键参数 / 限制

### 任务类型对比

| 能力 | 一次性 | 周期性 | 自主 |
| --- | --- | --- | --- |
| 时间表达式 | ISO datetime | cron（5 字段） | cron（5 字段） |
| 触发次数 | 固定 1 次 | 由 cron + 生效时间范围 + 最大次数共同决定 | 同周期性，且 Agent 可自主终止 |
| 每次的提示词 | 固定（创建时填写） | 固定（创建时填写） | 首次用初始提示词，后续由分析 Agent 生成 |
| 是否需要历史上下文 | 否 | 否 | 自动注入历史任务索引 |
| 结束条件 | 执行完毕自动禁用 | cron 调度、`valid_until` 到期或达到最大次数 | Agent 标记 `## 任务完成` / 达到最大次数 / Agent 无后续计划 |

### 任务字段

| 字段 | 说明 |
| --- | --- |
| `job_name` | 任务名称；同一 Agent 下不可重复 |
| `agent_id` | 关联的 Agent |
| `schedule_expression` | 一次性=ISO datetime；周期/自主=cron 表达式 |
| `timezone` | 调度用的时区（IANA），默认 `UTC` |
| `prompt` | 触发时发送给 Agent 的提示词 |
| `description` | 任务描述，方便管理 |
| `max_executions` | 最大执行次数，超出后自动停用 |
| `valid_from` / `valid_until` | 生效时间窗口（ISO datetime） |
| `model_override` | 覆盖默认模型（例如用更便宜的模型跑日常任务） |
| `enabled` | 是否启用 |

### 调度器运行参数（平台默认值）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 任务（Job）扫描间隔 | 60 秒 | 每隔多久检查一次所有启用任务并为它们生成下次待执行记录 |
| 执行（Task）扫描间隔 | 10 秒 | 每隔多久检查一次到期待执行记录并启动 Agent |
| 最大并发执行数 | 5 | 同时最多几个 Agent 在跑，超出的会推迟到下一轮 |
| 单次执行超时 | 3600 秒 | Agent 单次运行墙钟上限 |
| 卡死阈值 | 7200 秒 | 执行中状态超过此时长会被视为异常 |
| 分析 Agent 模型 | 轻量模型 | 默认用更便宜的模型做结果总结，降低成本 |
| 空结果标识 | `HEARTBEAT_OK`、`NO_ACTION_NEEDED`、`NOTHING_TO_REPORT`、`TASK_SKIPPED` | Agent 回复这些字样时摘要被自动设为"无需操作" |
| 结果摘要最大长度 | 1000 字 | 分析 Agent 生成的摘要上限 |
| Agent 输出单文件上限 | 10 MiB | 超出的输出将被截断 |

### 时区、cron、时间相关

- cron 使用标准 5 字段：`分 时 日 月 周`；例如 `*/15 * * * *` 表示每 15 分钟一次。
- 时区支持 IANA 名称（如 `Asia/Shanghai`、`America/New_York`），平台内部转为 UTC 执行。
- 一次性任务不检查 `valid_until`——到点就触发，避免过期跳过。
- 周期性 / 自主任务在 `valid_until` 之后不再生成新执行，但已经生成的等待中执行仍会按计划跑完。

::: warning
如果分析 Agent 连续三次 JSON 解析失败，调度器会以"解析失败"的保守结果完成此轮，不会无限重试；自主任务不会因此终止，慢循环会按原节奏创建下一次执行。
:::

## 常见问题

**Q1：任务已经创建，但迟迟没有执行，怎么回事？**

A：先确认三点：1) 任务状态是「启用」；2) 当前时间在 `valid_from` 和 `valid_until` 之间；3) 没有超过最大执行次数。周期性 / 自主任务的 cron 表达式错误会在创建时被拦截；如果以上都没问题，调度器平均需要 10 秒（执行扫描间隔）才会到点触发。

**Q2：一次性任务的执行时间过了才创建，会跑吗？**

A：不会。调度器在扫描时发现该任务的 `schedule_expression` 已是过去时间，就不再创建新执行。已经被创建但还没跑的等待中执行，则不受影响。

**Q3：周期性任务上一轮还没跑完，下一轮到时间了会怎样？**

A：不会重叠。只有当前轮次进入 `completed` / `failed` / `skipped` 之后，慢循环才会创建下一个待执行记录。此外，每次执行从 `pending` 切到 `running` 都走原子更新（乐观锁），即使多实例部署也不会把同一次执行跑两遍。

**Q4：自主任务会一直跑下去吗？怎么让它停？**

A：三种方式都可以让它停下：1) 在 Agent 的提示词里让它在目标达成时回复 `## 任务完成`；2) 创建任务时设置「最大执行次数」作为硬上限；3) 手动禁用该任务。分析 Agent 还会做一次双重校验——如果 Agent 既没写 `## 下一步计划` 也没写 `## 任务完成`，且不是心跳回复，就会自动判定为终止。

**Q5：Agent 每次的输出会保留多久？能看历史吗？**

A：每次执行都有独立的 S3 工作空间（路径形如 `s3://&lt;bucket&gt;/&lt;event_job_id&gt;/&lt;task_id&gt;/`），`agent_response.out` 是 Agent 的完整原始输出，工作空间里的其他文件也会保留；任务级别的 `mission_log.md` 会追加每次的摘要索引。这些文件在任务被删除时会与执行记录一并级联删除。

**Q6：可以给调度任务指定一个更便宜的模型吗？**

A：可以。在任务的 `model_override` 字段里填入模型 ID，就会在执行时覆盖 Agent 的默认模型；结果分析用的分析 Agent 平台默认就跑在轻量模型上。
