# 技能系统

## 这是什么

技能（Skill）是一份打包好的"专项能力"，里面包含一份说明文档（`SKILL.md`）、可选的脚本、参考资料、子代理和评估数据。把技能挂到智能体上，智能体在遇到对应任务时会自动加载对应能力并执行相关脚本。

技能系统帮你：把团队沉淀的标准流程、最佳实践、自动化脚本打包成可分发、可复用、可版本化的能力包，在不同智能体、不同项目之间共享。

## 使用场景

| 场景 | 说明 |
|------|------|
| 给智能体扩展专业能力 | 给一个通用对话智能体挂上"PPT 生成""Excel 处理""代码审查"等技能，让它在需要时自动调用 |
| 复用社区已有成果 | 从 GitHub 批量引入公开仓库里的技能包（如 Anthropic 官方 skills） |
| 跨项目共享工作流 | 把一组常用自动化脚本打包成技能，供多个智能体、多个项目复用 |
| 沉淀团队 SOP | 把团队内部的标准操作流程（SOP）做成技能，新成员的智能体装上即可使用 |

## 如何使用

### 1. 浏览技能库

打开「技能库」页面，可以看到所有技能的卡片列表。顶部支持按**分类**、**标签**、**技能类型**（系统 / 平台生成 / 社区 / 私有）筛选，以及关键词搜索（匹配名称、描述、标签）。

每张卡片显示技能名称、一句话摘要、脚本/子代理徽章、收藏数、使用次数。

### 2. 查看技能详情

点击任意技能卡片进入详情页，可以看到：

- 完整的 `SKILL.md` 内容（使用说明、调用示例）
- 文件清单（按类型分组：说明文档、脚本、参考资料、子代理、资源、评估、配置）
- 版本号、来源（GitHub 仓库 / URL / 本地 / 平台生成）
- 可执行脚本列表

<!-- SCREENSHOT: skill-detail -->

### 3. 导入技能

点击「导入技能」按钮，支持四种来源：

| 来源 | 输入 | 适用场景 |
|------|------|---------|
| `GitHub 仓库` | 仓库 URL + 可选路径 | 社区公开仓库；或从单仓多技能的目录中挑选 |
| `URL` | 直接指向 `SKILL.md` 的链接 | 只需要一份说明文档的简单技能 |
| `Claude Code 本地目录` | 本地路径 | 把本机已有的 Claude Code 技能批量扫描入库 |
| `本地目录` | 任意包含 `SKILL.md` 的目录 | 从工作目录把写好的技能导入平台 |

导入时平台会：

1. 获取文件并解析 `SKILL.md` 的 frontmatter（name、description、tools、version）
2. 递归收集所有标准子目录：`scripts/`、`references/`、`assets/`、`agents/`、`eval-viewer/`、`evals/`、`config/`
3. 写入本地 + 上传 S3 + 登记元数据
4. 自动按来源创建或匹配一个**技能分组**（例如 `owner/repo`）

### 4. 批量导入 GitHub 仓库

当一个 GitHub 仓库里有多个技能（例如 `skills/` 下有几十个子目录）时：

1. 选择「GitHub 批量导入」，填写仓库 URL 和基础路径（如 `skills`）
2. 平台扫描后返回预览列表：每个技能的名称、文件数、总大小、本地是否已存在
3. 勾选想要导入的技能，点击「确认导入」
4. 平台按顺序抓取并入库，本地已存在的会更新

<!-- SCREENSHOT: skill-batch-scan -->

### 5. 创建或修改技能

点击「新建技能」：

1. 填写技能名称、一句话描述、分类、标签
2. 撰写 `SKILL.md` 正文（支持 frontmatter 声明可用工具）
3. 可选：上传脚本、参考资料、子代理等文件
4. 设置为公开或私有
5. 保存后即在技能库中可见

编辑已有技能时，更新内容会同步刷新本地、S3 与元数据，并自动更新 `l1_summary`、`updated_at` 等字段。

### 6. 把技能挂到智能体

在智能体的配置页选择「添加技能」，勾选需要的技能即可。智能体会按"渐进式加载"使用它们：

- **对话开始** — 只加载每个技能的摘要（轻量）
- **命中触发条件** — 展开完整 `SKILL.md` 与 `references/` 参考资料
- **需要执行操作** — 调用 `scripts/` 里的脚本

### 7. 执行技能脚本

技能中 `scripts/` 目录下的脚本可以由智能体或平台直接执行。支持的运行时：

| 扩展名 | 运行时 |
|--------|--------|
| `.py` | python |
| `.sh` | bash |
| `.js` | node |
| `.ts` | ts-node |

执行时平台会自动注入环境变量 `SKILL_ID`、`SKILL_NAME`、`SKILL_DIR`，默认超时 **120 秒**，结果包含标准输出、标准错误、返回码、耗时。

## 关键参数 / 限制

| 项目 | 取值 / 说明 |
|------|------------|
| 技能类型 | `system`（系统内置）/ `generated`（平台生成）/ `community`（社区导入）/ `private`（私有） |
| 必须文件 | `SKILL.md`（根目录） |
| 标准子目录 | `scripts/`、`references/`、`assets/`、`agents/`、`eval-viewer/`、`evals/`、`config/` |
| 脚本运行时 | python、bash、node、ts-node；混用时标记为 `mixed` |
| 脚本默认超时 | 120 秒 |
| 脚本输出截断 | stdout 最后 5000 字符、stderr 最后 2000 字符 |
| 来源类型 | GitHub、URL、Claude Code、手动、平台生成 |
| 摘要字段 | L1 摘要自动截取 description 前 200 字符 |
| 批量扫描 | 仅支持 GitHub URL |
| 分组 | 按来源自动分组（例如一个 GitHub 仓库对应一个分组），也可建立"组合"虚拟分组 |
| 存储层 | 本地目录 + S3（按 `skill_type/skill_id/` 分层） + 元数据库 |

## 常见问题

**Q: 技能和子代理有什么区别？**
技能是"能力包"，静态存储，被智能体或主代理按需加载；子代理是运行时的独立角色，由主代理调度来完成一个子任务。一个技能内部可以包含 `agents/` 目录，这些子代理就是该技能附带的专用角色。

**Q: 导入相同名字的技能会冲突吗？**
不会覆盖。平台按"技能名 + 来源"判断是否是同一个技能：同一个 GitHub 仓库下的同名技能会视为更新，内容哈希（`import_hash`）变化才会重新写入；不同来源的同名技能会分别保留。

**Q: 导入后在本地哪里？**
技能按类型分目录存放：`system_skills/`、`generated_skills/`、`community_skills/`、`private_skills/`，每个技能一个子目录，里面就是原始的 `SKILL.md` 和各类文件。S3 侧还会保留一份备份，本地丢失时会自动同步回来。

**Q: 技能的版本怎么管理？**
在 `SKILL.md` 的 frontmatter 里声明 `version`（例如 `1.0.0`）。重新导入或更新时，平台会把版本号写入元数据；如果来源有新版本，导入时会覆盖旧版。

**Q: 执行脚本安全吗？**
脚本在独立子进程中运行，有超时保护（默认 120 秒），标准输出和标准错误都会被截取长度。建议：不要在技能里放会访问生产数据的脚本；通过环境变量传入上下文而不是硬编码。
