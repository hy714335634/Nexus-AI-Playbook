# 工作流引擎

## 这是什么

工作流引擎是 Nexus-AI 把「一句自然语言需求」拆成若干可追踪阶段并按顺序跑完的调度中枢。当你在平台上发起「构建 Agent」「更新 Agent」「构建工具」「构建 Skill」或用「Magician 智能路由」自动分流时，后台都是工作流引擎按预定义阶段推进：意图识别 → 需求分析 → 设计 → 开发 → 验证 → 部署，并在过程中保存上下文、聚合指标、响应暂停/恢复/停止等控制信号。

## 使用场景

| 场景 | 工作流引擎帮你做什么 |
| --- | --- |
| 首次描述一个 Agent 需求 | 走 `Agent 构建工作流`：意图识别、需求分析、架构设计、Agent 设计、工具开发、提示词开发、代码开发、部署共 8 个阶段 |
| 想改已有 Agent 的能力或提示词 | 走 `Agent 更新工作流`：更新编排、需求更新、工具更新、提示词更新、部署共 5 个阶段，可选择跳过其中的工具/提示词阶段 |
| 想单独构建一个工具函数 | 走 `工具构建工作流`：意图识别 → 设计 → 开发 → 验证 → 部署，5 个阶段 |
| 想构建一个 Claude 风格 Skill | 走 `Skill 构建工作流`：意图识别 → 设计 → 开发 → 验证 → 部署，5 个阶段 |
| 不确定需求对应哪种工作流 | 走 `Magician 智能路由`：自动识别意图并分发到合适的工作流 |
| 长任务跑一半想中断或回看 | 支持暂停、恢复、停止；每一步的输出、token 消耗、执行耗时都会被完整保存，可从任意已完成阶段继续 |
| 多 Agent 项目并行构建 | 架构设计阶段会按 Agent 数量自动 fork，开发阶段并行推进，部署前汇聚（join） |

## 如何使用

### 方式一：一次性跑完整个工作流

<!-- SCREENSHOT: workflow-engine-run-full -->

1. 在「新建项目」页面选择目标工作流（Agent 构建 / 工具构建 / Skill 构建 / Agent 更新 / Magician）。
2. 用自然语言写下你的需求，描述越具体，意图识别阶段越准。
3. 提交后工作流引擎会按配置的阶段顺序依次推进，直到最后一个阶段完成。
4. 在项目详情页可以实时看到：
   - 当前阶段与已完成阶段列表；
   - 每个阶段的输入/输出 token、执行耗时、工具调用次数；
   - 聚合后的总 token 消耗、总耗时、总工具调用次数。

### 方式二：从某个阶段开始执行

当某个阶段的结果你想重新生成（比如提示词改了、工具需求变了），可以从该阶段重新跑：

1. 进入项目详情页。
2. 点击某个已完成阶段右侧的 `从此处重跑`。
3. 平台会校验其前置阶段是否都已完成；若缺失前置，会提示你先补齐（或从更早的阶段重跑）。
4. 确认后，工作流引擎会从该阶段开始，一路执行到结束。

::: tip 前置校验是硬性约束
每个阶段在工作流配置里都有 `prerequisites`。例如 `代码开发` 依赖 `提示词开发`，没有提示词就不能开工。如果你试图跳过前置，平台会直接拒绝并告诉你缺了哪些阶段。
:::

### 方式三：暂停、恢复、停止

<!-- SCREENSHOT: workflow-engine-pause-resume -->

在长任务（尤其是工具/提示词/代码开发阶段，可能跑几分钟甚至几十分钟）中：

1. 点击项目页顶部的 `暂停`。当前阶段完成后工作流会停在那里，不再触发下一阶段。
2. 点击 `恢复`，工作流从下一个待执行阶段继续。
3. 点击 `停止`，工作流会在当前 LLM 调用结束后整单停下，状态标记为 `stopped`，不会再自动推进。
4. 任何时候都可以在项目页查看当前控制状态：`running` / `paused` / `stopped` / `cancelled`。

### 方式四：多 Agent 项目的 fork / join

当你的需求需要多个协作 Agent（例如主 Agent + 若干子 Agent），`Agent 构建工作流` 会自动按以下规则并行：

1. `系统架构设计` 完成后，平台读取架构里的 Agent 清单。
2. 对每个 Agent 并行执行 `Agent 设计 → 工具开发 → 提示词开发 → 代码开发` 四个 agent-scope 阶段。
3. 所有 Agent 的代码开发都完成后，自动汇聚（join）进入 `Agent 部署` 阶段，统一部署。
4. 项目页的进度视图会按 Agent 分组显示每个 Agent 当前走到了哪一步、总进度百分比。

### 方式五：Magician 智能路由

如果你描述的是一个混合需求（"给我做个能查天气再根据天气推荐穿搭的 Agent"之类），可以把它交给 Magician：

1. 在「新建项目」选择 `Magician 智能路由`。
2. 输入完整需求。
3. Magician 会识别你的意图——新建 Agent、更新 Agent，还是只做工具？然后自动跳转到对应的工作流继续跑后续阶段。

## 关键参数 / 限制

### 工作流与阶段

| 工作流 | 阶段数 | 阶段顺序 |
| --- | --- | --- |
| Agent 构建工作流 V2 | 8 | 意图识别 → 需求深度分析 → 系统架构设计 → Agent 设计 → 工具开发 → 提示词开发 → 代码开发 → Agent 部署 |
| Agent 更新工作流 V2 | 5 | 更新编排 → 需求更新分析 → 工具更新 → 提示词更新 → 更新部署 |
| 工具构建工作流 V2 | 5 | 意图识别 → 工具设计 → 工具开发 → 工具验证 → 工具部署 |
| Skill 构建工作流 | 5 | 意图识别 → Skill 设计 → Skill 开发 → Skill 验证 → Skill 部署 |
| Magician 智能路由 | 1 | 智能编排（自动路由到其它工作流） |

### 阶段属性

| 属性 | 含义 |
| --- | --- |
| `scope` | `project`（项目级，全局一次）或 `agent`（Agent 级，每个 Agent 执行一次） |
| `prerequisites` | 必须先完成的前置阶段列表；未完成时当前阶段无法启动 |
| `supports_iteration` | 阶段是否支持多轮迭代（工具/提示词/代码开发默认为 true） |
| `optional` | 阶段是否可跳过（`Agent 更新工作流` 中的工具更新、提示词更新为可选） |
| `fork_on_complete` | 完成后按 Agent 数量 fork 出并行分支（`系统架构设计` 为 true） |
| `join_after_complete` / `join_before_start` | 是否在此处汇聚所有 Agent 分支（`代码开发` 完成后汇聚，`Agent 部署` 开始前汇聚） |
| `rule_keys` | 注入到阶段上下文的规则键，如 `directory_rules`、`generation_rules`、`cache_rules`、`external_resources`、`custom_rules` |

### 默认运行时配额

| 配额 | 默认值 | 说明 |
| --- | --- | --- |
| 单阶段失败最大重试次数 | 3 | 达到上限后整单标记为 `failed` |
| 重试间隔 | 5 秒 | 两次重试之间的等待时间 |
| 单阶段超时 | 3600 秒（1 小时） | 超时即判定为失败 |
| 总工作流超时 | 21600 秒（6 小时） | 整个工作流的墙钟上限 |
| 检查点保存间隔 | 60 秒 | 执行过程中多久落一次状态 |
| 上下文最大 token | 100000 | 注入给 Agent 的上下文上限 |
| 摘要触发阈值 | 5000 token | 单个已完成阶段输出超过此值会自动摘要 |
| 阶段输出最大内联大小 | 400 KB | 超过后内容改为引用外部对象存储 |

### 工作流与控制状态

| 状态类型 | 可能值 | 含义 |
| --- | --- | --- |
| 阶段/项目状态 | `pending` / `running` / `completed` / `failed` / `paused` | 对应阶段生命周期 |
| 控制状态 | `running` / `paused` / `stopped` / `cancelled` | 对应用户的暂停、停止、取消操作 |

## 常见问题

**Q1：我从某个阶段重跑，前置阶段需要重新跑吗？**
A：不需要。只要前置阶段在历史里是 `completed` 状态，引擎就认为可用，直接从你指定的阶段开始。但如果前置其实从未完成，或你改了更早阶段的输出，必须先把前置跑完，引擎会拒绝跳步执行。

**Q2：暂停和停止有什么区别？**
A：暂停是「做完手头这个阶段就停」，恢复后从下一个待执行阶段继续，常用于想中途查看结果。停止是「做完当前这次 LLM 调用就收尾」，整单状态变成 `stopped`，不会自动恢复；如果想继续，需要手动从某阶段重跑。

**Q3：`Agent 更新工作流` 能只改提示词、不改工具吗？**
A：可以。更新编排阶段会分析你的需求，自动决定哪些阶段可以跳过（`skip_stages`）。工具更新、提示词更新在配置里标记为 `optional: true`，只有需要时才会执行，被跳过的阶段不会消耗额度。

**Q4：多 Agent 项目里有一个 Agent 构建失败，其它会怎样？**
A：每个 Agent 分支互相独立，一个 Agent 在工具/提示词/代码开发阶段失败，只会把它自己的阶段标记为 `failed`，不影响其它 Agent 继续推进。但 `Agent 部署` 阶段是 join 汇聚点，只有所有 Agent 的代码开发都成功才会触发统一部署；否则部署会等到你把失败的 Agent 修好再重跑。

**Q5：阶段输出的执行指标去哪看？**
A：每个阶段完成后都会记录 `input_tokens` / `output_tokens` / `execution_time_seconds` / `tool_calls_count` / `model_id`；项目页的概览卡片会把它们聚合为总 token、总成本、总耗时、总工具调用次数。
