# 流式响应中继

## 这是什么

流式响应中继让 Agent 的回答像打字机一样逐字出现，并把整轮输出缓存在服务端。你可以随时切换标签、刷新浏览器，甚至短暂断网——回到原会话时还能从上次的位置继续看完，不丢任何一条消息或工具调用。

## 使用场景

| 场景 | 你做了什么 | 中继帮你做了什么 |
| --- | --- | --- |
| 长任务跑到一半切走 | Agent 正在执行多步骤任务，你切到别的会话或别的标签 | 回到原会话后，输出从断点继续呈现，直到任务结束 |
| 浏览器意外断开 | 网络闪断、电脑休眠、页面崩溃 | 重连后自动续传，无需重新发问,、无需重复执行任务 |
| 多端同时查看 | 同一会话在手机和电脑上都打开 | 两端各自独立订阅同一份流，内容保持一致 |
| 回看刚刚的输出 | 想再确认一下刚看到的那条回答 | 短时间内重新进入会话，历史事件会一次性回放到最新位置 |
| 工具执行较慢 | Agent 在调用一个耗时的工具 | 连接不会被代理或浏览器超时切断 |

## 如何使用

流式响应中继是**默认行为**，无需手动开启。下面描述你作为用户能感知到的动作。

1. **发起一次对话**
   在聊天界面输入问题并发送。Agent 开始逐字输出回答，工具调用（例如文件读写、网页搜索）以卡片形式实时出现在流中。
   <!-- SCREENSHOT: stream-relay-typing -->

2. **切换标签或离开页面**
   随时点击侧边栏切到别的会话。原会话的任务在后台继续执行，输出仍在累积。

3. **回到原会话**
   点击侧边栏回到那个会话。你会看到：
   - 先是错过的内容**一次性渲染**到屏幕上（历史追赶阶段）
   - 随后界面自然过渡到**实时流式**模式，继续接收新事件
   <!-- SCREENSHOT: stream-relay-catchup -->

4. **（可选）查看会话运行状态**
   想知道某个会话是否还在跑，顶部状态指示会显示以下三种之一：`进行中` / `已完成` / `出错`。

5. **任务结束**
   Agent 输出完毕后，最终消息被写入消息历史，工具卡片折叠为摘要。之后再进入这个会话时，直接从消息历史加载——不再走流式中继。

::: tip
短时间断开（数十秒以内）重连几乎无感；断开过久则原始流可能已过期，此时界面会提示"请从消息历史加载"——打开会话后依然能看到已经保存的完整对话。
:::

## 关键参数 / 限制

| 项 | 说明 |
| --- | --- |
| 自动重连 | 切标签、刷新、短时间断网都会自动续传，无需手动操作 |
| 保留时长 | 单次任务的流式事件在服务端保留有限时间；任务结束并超过保留窗口后，需从消息历史加载 |
| 多端订阅 | 同一会话可在多个浏览器标签或设备上同时订阅，内容一致，不会重复执行任务或重复计费 |
| 工具调用摘要 | 为避免传输过大，流中的工具输入会截断到 100 字符、工具结果截断到 2000 字符；完整内容可在工作空间文件面板中查看 |
| 空闲心跳 | 连接空闲时服务端每 15 秒发送一次心跳，防止中间代理断开连接 |
| 追赶完成信号 | 返回原会话时，系统会在"历史回放结束、即将转入实时"那一刻发出一次信号，前端据此切换渲染模式 |
| 结束条件 | 任务发出 `完成` 信号并清空缓冲后，流不再可用；Agent 侧出错时同样不可用 |
| 权限 | 流式相关功能需要你具备与该 Agent 对话的权限 |

## 常见问题

**Q：我切走再回来，为什么有时候历史内容是一次性蹦出来的，有时候是逐字的？**
A：如果离开时任务已完成，回来只看到已写入历史的整段消息；如果任务还在跑，回来时会先一次性补齐你错过的部分，再进入实时打字模式。

**Q：断网很久之后再回到页面，内容丢了怎么办？**
A：流式缓存是临时的。只要任务正常完成，完整消息会写入消息历史，从侧边栏重新进入会话即可看到全部内容，不会丢失。

**Q：我同时在手机和电脑上打开同一个会话，会冲突吗？**
A：不会。两端各自订阅同一份服务端流，内容完全一致，不会互相干扰，也不会让 Agent 重复执行任务。

**Q：页面顶部出现"已过期或不存在"的提示，意味着什么？**
A：说明流式缓存已超过保留窗口。历史消息不会丢，直接从消息列表加载即可；只是不再能看到"逐字出现"的过程。

**Q：为什么流中看到的工具调用输出被截断了？**
A：为了流畅体验，流式事件里只传工具调用的摘要。要看完整内容，去会话的工作空间文件面板中找对应文件预览或下载。
