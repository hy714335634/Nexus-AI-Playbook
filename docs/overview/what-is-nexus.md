# 什么是 Nexus-AI

Nexus-AI 是一个基于 AWS 云端架构的 **AI Agent 自动化构建平台**。它采用独创的 **"Agent Build Agent"** 理念 —— 用 AI Agent 来构建 AI Agent。你只需用自然语言描述业务需求，平台内部的 8 个专业 AI Agent 就会自动协作，为你构建出一个完整的、可对话交互的 AI Agent。

## 为什么需要 Nexus-AI

### 传统方式的痛点

在传统的 AI Agent 开发流程中，构建一个可用的 Agent 通常面临以下挑战：

| 挑战 | 说明 |
|------|------|
| **开发周期长** | 从需求分析到部署上线，可能需要数周甚至数月 |
| **技术门槛高** | 需要掌握编程、提示词工程、工具集成、模型调优等多项技术 |
| **协作成本高** | 需要产品经理、架构师、开发工程师、测试工程师等多角色配合 |
| **迭代困难** | 修改需求往往意味着大量代码返工 |
| **质量不稳定** | 提示词设计、工具开发、代码实现的质量高度依赖人员经验 |

### Nexus-AI 的解决方案

Nexus-AI 将整个 Agent 开发流程自动化，把原本需要多人协作的复杂工程，变成一次自然语言对话：

```
传统方式：
  产品经理(需求分析) → 架构师(方案设计) → 工程师(代码开发)
  → 测试工程师(质量验证) → 运维工程师(部署上线)
  ⏱️ 数周 ~ 数月

Nexus-AI 方式：
  用户(自然语言描述) → 8 个 AI Agent 自动协作 → 可用的 Agent
  ⏱️ 几分钟 ~ 十几分钟
```

## 设计理念

Nexus-AI 的设计基于三大核心理念：

### Agentic AI Native

平台以 **"AI Agent 原生"** 的理念设计 —— 每个模块、每个功能，甚至每个按钮背后，都可以是一个 AI Agent。整个平台本身就是由 Agent 驱动的系统。

### Agent as Software

**"用 Agent 来构建 Agent"** —— 不仅用 AI Agent 为用户构建业务 Agent，平台自身也通过 Agent 进行自我迭代和优化。这意味着平台会随着使用越来越"聪明"。

### Agent = 数字员工

每个 Agent 都被视为一个 **数字员工** —— 拥有独立的身份、专业技能和工作职责。Agent 之间可以自由通信和协作，形成一个 Agent 关系网络，就像一个数字化的组织。

::: tip 业务人员即构建者
Nexus-AI 的核心假设是：**业务人员既是用户也是构建者**。平台假设使用者没有任何 IT 知识背景，只需要专注于业务需求本身。Agent 的能力取决于企业特有的业务理解、数据和流程，并且随着使用不断成长。
:::

## 核心价值

Nexus-AI 的长期愿景是成为企业 AI Agent 生态的专属基础设施，实现 **"人人可开发 AI Agent"**，让 AI Agent 技术真正普惠化。

| 核心价值 | 说明 |
|----------|------|
| **专家级构建能力** | 为业务和 IT 人员提供专家级的 Agent 构建能力，无需深度技术背景 |
| **极速交付** | 将 Agent 构建时间从数天缩短到数十分钟，与企业发展同步迭代 |
| **安全可靠** | 基于 AWS GenAI 服务（Bedrock、AgentCore），构建安全可靠的企业级 Agent |
| **持续积累** | 不断丰富行业工具库，为深度业务 Agent 提供基础能力储备 |

### AgentBase —— 智能资产积累

随着平台的持续使用，系统会逐步积累 **AgentBase（智能资产库）**：

- **Agent 库** — 已构建的 Agent 可被索引和复用
- **工具库** — 已开发的工具函数可被新 Agent 共享使用
- **提示词库** — 高质量的提示词模板可被复用和优化

AgentBase 支持 Agent 之间的复杂协作、知识共享和工具共享，使得新 Agent 的构建越来越快、质量越来越高。

## 业务人员与 IT 人员的分工

Nexus-AI 为业务人员和 IT 人员提供了清晰的分工：

| 角色 | 职责 |
|------|------|
| **业务人员** | 创建和使用 Agent、管理 Agent 版本和标签、迭代 Agent 功能、业务需求理解和表达、自助排障 |
| **IT 人员** | 提供和优化高质量工具和 MCP、提供内部系统集成工具、平台运维和监控、安全防护策略 |

简单来说：**业务人员负责"做什么"，IT 人员负责"怎么做得更好"**。

## 核心理念：Agent Build Agent

Nexus-AI 的核心创新在于 **"用 AI Agent 来构建 AI Agent"**。平台内部由 **8 个高度专业化的 Builder Agent** 组成一支完整的"AI 开发团队"，它们各司其职、自动协作：

| Builder Agent | 角色类比 | 核心职责 |
|--------------|----------|----------|
| **Orchestrator（编排调度）** | 项目经理 | 分析需求复杂度，制定构建计划，协调各阶段任务路由和进度 |
| **Requirements Agent（需求分析）** | 产品经理 | 将自然语言需求转化为结构化规格，通过智能提问填补需求盲区 |
| **Architecture Agent（系统架构）** | 系统架构师 | 设计 Agent 技术架构、组件规划、集成映射 |
| **Design Agent（Agent 设计）** | 交互设计师 | 定义行为模式、交互流程、错误处理策略、用户体验 |
| **Prompt Agent（提示词工程）** | 提示词专家 | 编写系统提示词、指令优化、角色人设定义 |
| **Tools Agent（工具开发）** | 工具工程师 | 开发工具函数、API 集成、功能测试 |
| **Developer Agent（代码开发）** | 软件工程师 | 生成 Agent 主程序代码、模块整合、单元测试 |
| **DevManager Agent（开发管理）** | 技术经理 | 代码审查、质量保证、集成测试、规范检查 |

最终由 **Agent Deployer** 完成部署上线，使构建好的 Agent 可以被用户直接调用。

::: tip 通俗理解
想象你有一支随时待命的 AI 开发团队。你只需告诉"项目经理"你想要什么，这支团队就会自动分工、协作，在几分钟内交付一个完整的 AI Agent —— 包括代码、工具、提示词，一应俱全。
:::

## 核心能力

### 自然语言输入

不需要编程知识，用中文或英文描述你的业务需求即可。平台能准确理解各种复杂的业务场景描述。

**示例需求：**
> "帮我创建一个医学文献研究助手，能够在 PubMed 上搜索论文、解析 PDF 全文、提取关键数据，并按照 APA 格式生成引用列表。"

> "我需要一个 AWS 云服务报价 Agent，能根据客户的使用场景推荐合适的 AWS 服务组合并估算月度费用。"

> "创建一个能分析 CSV 和 Excel 数据文件的 Agent，支持数据清洗、统计分析、可视化图表生成。"

### 智能需求澄清

当你的需求描述不够具体时，平台不会盲目开始构建。**Requirements Agent** 会通过智能提问，帮你补充和完善需求细节：

- 明确 Agent 的目标用户和使用场景
- 确定需要对接的数据源和 API
- 定义输入输出格式和交互方式
- 识别边界条件和异常处理策略

这种"引导式需求分析"确保最终构建的 Agent 真正满足你的实际需求。

### 全自动构建流水线

从需求到可用 Agent，整个过程全自动执行，涵盖 **9 个阶段**：

1. **编排调度** — 制定构建计划、任务分配
2. **需求分析** — 需求理解、细化、规格化
3. **系统架构** — 技术方案设计
4. **Agent 设计** — 行为逻辑和交互设计
5. **提示词工程** — 系统提示词编写和优化
6. **工具开发** — 工具函数开发和测试
7. **代码开发** — Agent 主程序代码生成
8. **开发管理** — 代码审查和质量保证
9. **部署上线** — 自动部署并使 Agent 可用

每个阶段都有专业的 Builder Agent 负责，产出物自动传递给下一阶段。你可以在 [构建进度](/manual/build-progress) 页面实时查看每个阶段的执行状态。

### 多模态输入

创建 Agent 时，除了文字描述，你还可以上传多种格式的附件来补充说明需求：

| 文件格式 | 用途 |
|----------|------|
| **图片** (JPG/PNG) | 展示期望的界面效果或参考设计 |
| **PDF 文档** | 提供产品说明、业务规范等参考材料 |
| **Excel 表格** (.xlsx) | 提供数据样本，帮助 Agent 理解数据结构 |
| **Word 文档** (.docx) | 提供详细的业务需求说明 |
| **CSV 文件** | 提供数据样本 |
| **纯文本** (.txt) | 任何文本格式的参考材料 |

这种多模态输入能力让 Agent 的构建更加精准 —— 你可以把产品文档、数据样本、界面截图一起发给平台，AI 会综合所有信息进行构建。

### 即构即用

构建完成的 Agent 可以立即投入使用：

- **在线对话** — 直接在平台内与 Agent 进行多轮对话交互
- **文件分析** — 上传文件让 Agent 分析处理
- **丰富输出** — Agent 可以返回 Markdown 格式文本、代码、表格、Mermaid 流程图等
- **会话记忆** — Agent 在同一会话中保持上下文连贯

### 能力扩展（MCP 集成）

通过 **MCP（Model Context Protocol）** 标准协议，Agent 可以无缝集成各种外部工具和服务：

- **AWS 云服务** — 查询价格、管理资源等
- **数据 API** — 连接各类数据接口
- **企业系统** — 对接内部业务系统
- **第三方服务** — 集成搜索引擎、数据库等

MCP 让 Agent 的能力不再局限于预置功能，可以按需扩展到任何外部服务。

### 灵活部署

构建好的 Agent 支持两种部署方式：

| 部署方式 | 说明 | 适用场景 |
|----------|------|----------|
| **本地部署** (Local) | 运行在 Nexus-AI 服务器上 | 开发测试、内部使用、快速验证 |
| **云端托管** (AgentCore) | 托管在 AWS Bedrock AgentCore | 生产环境、高可用、自动扩缩容 |

## 自我进化闭环

Nexus-AI 不是一个"用一次就结束"的工具，而是一个 **持续进化的闭环系统**。整个平台围绕"构建→管理→对话→反馈→迭代"的循环不断自我优化：

```
        ┌─────────┐
   ┌───→│  构 建   │───→ 新 Agent 诞生
   │    └─────────┘
   │         ↓
   │    ┌─────────┐
   │    │  管 理   │───→ 工具增强、工具补充
   │    └─────────┘
   │         ↓
   │    ┌─────────┐
   │    │  对 话   │───→ 使用 Agent，发现问题
   │    └─────────┘
   │         ↓
   │    ┌─────────┐
   │    │  反 馈   │───→ Agent 智能分析问题，生成修正方案
   │    └─────────┘
   │         ↓
   │    ┌─────────┐
   └────│  迭 代   │←─── Agent 智能分析需求变化，生成优化方案
        └─────────┘
```

**关键特性：**
- 系统使用 AI Agent 智能分析，提供 **自动化问题诊断、工具优化和系统改进方案**
- 持续提升已有 Agent 的能力水平，同时抬高新 Agent 的基础能力
- 整个过程伴随 **可观测性**（Observability）监控，确保质量可追踪

## 真实应用案例

### 案例一：医学文献研究助手

**用户需求：** "创建一个医学文献研究助手，能搜索 PubMed 论文、解析全文、提取关键数据并生成引用。"

**平台自动构建：**
- 自动开发 PubMed API 搜索工具

**最终效果：** 用户只需输入研究主题，Agent 即可搜索相关论文、提取关键数据、生成文献综述。

### 案例二：AWS 云服务咨询顾问

**平台自动构建：**
- 集成 AWS Pricing MCP 服务器
- 开发用量计算和费用估算工具
- 编写具备 AWS 解决方案架构师知识的提示词

**最终效果：** 用户描述业务场景，Agent 推荐合适的 AWS 服务组合、估算月度费用、给出优化建议。

### 案例三：数据分析助手

**用户需求：** "创建一个数据分析 Agent，能读取 Excel/CSV 文件，做统计分析和数据可视化。"

**平台自动构建：**
- 开发文件读取和数据解析工具
- 开发统计计算工具
- 开发图表生成工具
- 编写数据分析专家提示词
- 部署后即可使用

**最终效果：** 用户上传数据文件，Agent 自动识别数据结构，进行统计分析，生成可视化图表和分析报告。
